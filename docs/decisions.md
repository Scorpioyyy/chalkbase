# 决策记录

每条记录：背景 → 决策 → 理由 → （如适用）替代方案与为何放弃。

## 2026-09-27　Stage 0

### D1. `ExerciseInstance.text` 存原文，改写示例仍新写
背景：最初方案（KICKOFF.md 初稿）要求 `ExerciseInstance` 不存教材原文，理由是"标注模型不接触教材原文"。用户修正：取消该限制。
决策：`ExerciseInstance` 增加 `text` 字段存原文（图形部分用文字描述），供标注模型组与人工核对参照；`ItemArchetype.rewritten_examples` 仍由 Agent/模型新写，不得复述或改编某条 `text`。
理由：(1) 标注模型组看到原文能显著提升实体消解、题型粒度等金标质量；(2) 人工核对本来就需要对照原页面（找漏抽/误读），"不接触原文"从来不是核对环节存在的真实理由；(3) 改写示例要作为后续生成的参考范式，必须是新写的、经过模板与参数约束校验的题目，而不是教材原题的存档，这与是否存原文无关。
影响：`data/` 中会包含教材习题原文的结构化摘录。仓库为私有仓库，原文限于单题粒度的文字（不含整页版式/插图本身），风险可控；整页渲染图、OCR 整页原始文本仍严格限制在 `tmp/`，不入库。

**更新（2026-09-28）**：用户已将仓库切换为**公开**。原风险评估中"仓库私有"这一条支撑理由不再成立——`work/books/*/exercises.json` 里累计已有上千条单题粒度的原文摘录（不含整页版式/插图本身），现在任何人都可访问。用户明确知情并确认切换（未要求撤回已提交的 `text` 字段内容或改回私有），故按用户决定继续推进，不主动改动已有数据或阻塞后续抽取；仅在此记录风险前提已变化，供以后如需重新评估时查阅。整页渲染图/OCR原始文本仍严格不入库的规则不受此影响，继续执行。

### D2. Python 环境用 conda + pip 混装
决策：`conda create -n verichalk python=3.11`，包依赖用 pip 安装（PyMuPDF、pydantic 等在 conda-forge 与 PyPI 都有，PyPI 版本更新更及时），写入 `environment.yml` 的 pip 段。
理由：KICKOFF.md 明确要求 conda 环境；核心科学计算包用 pip 避免 conda-forge 源同步延迟。

### D3. tesseract 可用性
决策：通过 `conda install -c conda-forge tesseract` 装好 tesseract 5.5.3，含 `chi_sim`（简体中文）等 125 种语言包，`environment.yml` 已加入该 conda 依赖。
理由：KICKOFF.md 要求"先拿 2 页比较'渲染后直接看'与 OCR，选更可靠的方式"，需要 tesseract 可用才能做这个对比；conda-forge 上有现成 Windows 二进制，安装顺利，无需用户手动装系统级 tesseract。
后续：Stage 1 试点 g4b 时再做 2 页的直接看 vs OCR 对比，记录结论；预期直接渲染给视觉模型看的方式在数学教材（含公式、图形、方格图）上会更可靠，OCR 更适合做辅助校验或纯文字页的快速定位，但以实测为准。

### D4. DashScope 模型默认开启思考模式
实测（tmp/test_dashscope.py）发现 `qwen3.8-max`、`qwen3.8-flash`、`qwen3.7-plus`、`deepseek-v4.1-flash` 在**不传** `enable_thinking` 时默认仍产生 `reasoning_tokens`（即默认开启思考模式），必须显式传 `enable_thinking: false/true` 才能控制。`curriculum/annotate/client.py` 已在 `AnnotationRequest` 中把 `thinking` 设为必填字段并总是显式传递，避免意外产生思考开销。

### D5. 教材版本边界与 KICKOFF.md 初始假设不符（重要，影响 Stage 5 范围）
KICKOFF.md 原假设"上册新版、下册旧版"。Stage 0 逐本核对封面审核章与后记文字后发现：**新版（2022 课标，国家教材委员会专家委员会审核通过 2024）覆盖 `g1a g1b g2a g2b g3a g3b g4a g5a g6a` 共 9 本；旧版（2011 课标，教育部审定 2013）只有 `g4b g5b g6b` 3 本**。已同步修正 KICKOFF.md 第 5 节。
理由：这与教材"新课标逐年级滚动换版、目前仅四至六年级下册尚未跟进"的现实一致，用户只能获取现有出版物，无法自行补齐。
影响：Stage 5 的版本对齐工作量集中在 `g4b/g5b/g6b` 与其余 9 本之间，而非原先设想的"上下册各 6 本"均等对齐；这 3 本旧版下册在能力边界与知识点顺序上可能与前后相邻的新版形成更集中的冲突，需重点检查 `g3b→g4a→g4b→g5a` 与 `g4b→g5a`、`g5b→g6a` 等跨版本衔接处。

## 2026-09-27　Stage 1（g4b 试点）

### D6. 无文字层书：渲染直接看 vs OCR（tesseract chi_sim）对比，采用前者
背景：`g4b`（数学四年级下册）全书无文字层，KICKOFF 要求先拿 2 页做对比再决定抽取方式。抽取前用 `scripts/inspect_book.py` 以 150 DPI 渲染 PDF 第8页（"小数的意义（二）"，含刻度尺、分数/小数对照、千克换算填空）与第20页（"歌手大赛"，含小数加减混合运算竖式与笔算过程）两页内容页，分别用 Read 工具直接看图，并对同两张图跑 `tesseract p0XX.png stdout -l chi_sim`。
决策：本次及后续 g4b 全书抽取一律采用"渲染后直接看图（多模态读图）"，不使用 OCR 结果作为抽取依据；OCR 仅可能用于快速定位文字密集页面的辅助检索，不用于核对数值。
理由：直接读图能准确识别全部文字、算式、竖式、分数记号（如 1/100、1/1000）与图形要素（刻度尺读数、天平/电子秤示数），无遗漏无误读。同一两页的 tesseract 结果错误密集且集中在关键数值和专名上，例如：
  - 第8页："鹌鹑蛋和鸵鸟蛋" 被识别成"蕉况蛋和能鸟蛋"；"12克=(　)千克=(　)千克" 的括号填空结构识别为乱码"12克=人千克= ( 上秆克，cat )千克"，分数线/括号完全丢失。
  - 第20页（危害最大的一类：手写体算式数字错读）："9号选手" 被识别成"9中兴于"；竖式运算结果 `8.65+0.40=9.05` 中的 "9.05" 被识别成 "4.05"（十位数字误读，且没有输出完整算式，直接影响能否正确抽取 `text`/`operand_features`）；`9.43-(8.65+0.40)` 整行被识别成 "94.43- (365+040)"，`=9.43-9.05` 被识别成 "=4.43-4.05"，小数点和数字均出现系统性错误。
  - OCR 对手写体/艺术字标题（如"歌手大赛"绿色圆角标题框内文字）识别率也明显低于印刷体正文。
  这类数值级错误若被用作抽取依据，会直接污染 `ExerciseInstance.text` 与 `operand_features` 的准确性，且错误具有隐蔽性（看起来像合理数字，不易被后续校验脚本发现），风险远高于人工读图的疏漏风险。多模态直接读图不存在这类系统性数字误读，且能同时理解版式与图形语义（如判断某图是"天平"还是"电子秤"），更符合抽取指南"图形部分用文字描述补全"的要求。
替代方案：曾考虑"OCR 结果 + 人工看图双重核对"，因 OCR 错误率过高、核对成本接近于重新看一遍图，对 g4b 全书 9 单元的体量不划算，放弃；保留 OCR 作为未来"批量定位关键词出现页码"等检索场景的备用工具。

## 2026-09-28　Stage 1 试点验收（用户核对后拍板）

用户核对了 g4a/g4b 各2页共5页抽取样本，确认无误，并对试点报告提出的4个歧义点逐条拍板，已写入 `docs/extraction_guide.md`：

### D7. ExerciseInstance 拆分规则：只看编号，不看内容条数
决策：有独立小题号/子编号才拆分成多条 `ExerciseInstance`；没有编号的批量算式/填空/判断题（即使列了好几项），整体记为 1 条。
理由：用户直接拍板"整体合一条"，选择更简单、更少歧义的规则（"看编号"是唯一需要判断的信号，不需要再区分"是否共享数据""是否为展示规律而分组"等更细的例外，降低后续 10 本书抽取时不同 agent 之间的判断分歧）。

### D8. 跨年级前置知识占位：直接建为正式知识点
决策：本书内找不到 KP 可挂靠的、明显是低年级已学的内容，在本书内新建为正式知识点（不是临时占位标记），交给 Stage 2 实体消解处理。
理由：用户拍板"是新知识点"；这与《抽取指南》§1"拿不准时倾向于分开记录"的既有原则一致，不需要额外发明占位标记体系。

### D9. 图片信息判读不清：维持默认渲染分辨率，不做二次高清核实
决策：无法判读的图片信息（算盘、身份证号等，g4a/g4b 试点共约7处）如实标注"未能判读"，不追加更高 DPI 重渲染核实。
理由：用户确认"不用使用更高DPI重新核实了"，成本收益不划算；这类缺口占比极低（430+535条实例中约7条），不影响下游可用性。

## 2026-09-28　Stage 1（g5a 抽取发现，已核实）

### D10.「面积」在 g1~g4（8本）中完全缺失，核实为真实的课标编排，非漏抽
背景：g5a 抽取汇报"g1~g4 全部8本书检索不到任何面积知识点，唯独周长教过"，标记为需要复核的异常（不确定是本书首次引入，还是 g3b 等书漏抽）。
核实过程：(1) 对已完成的 g1a/g1b/g2a/g2b/g3a/g3b/g4a/g4b 共8本书的 `knowledge_points.json` 做"面积"关键字全文检索，确认 0 条真实命中（g4b 的一条命中是"用字母表示数"误配，非面积）。(2) 检查 g3b（三年级下册，新版 2022 课标）目录，确认有"第三单元 周长"但确实没有"面积"单元。(3) 检查 g4a（四年级上册，新版）目录与已抽取的"图形的奥秘"单元内容（切开立体图形/分层方格图纸搭建/正方体翻滚周期），确认该单元讲的是立体图形截面与空间想象，同样不含面积测量。
结论：这**不是抽取遗漏**，而是本套教材（新版，依据2022课标）把"面积"的系统学习编排到了五年级上册（g5a），与传统教材"三年级学周长和面积"的常见顺序不同，是真实的课标/教材设计差异。
影响：下游 Stage 6 能力边界推导时，四年级及以前的课时边界应不含"面积"相关能力（长度×宽度、面积单位换算等），这是编写题目年级约束校验时的一个重要边界点，需要在能力边界数据里如实反映，不能假设"三年级应该会算面积"这类常见但对本教材不成立的默认认知。

## 2026-09-29　Stage 1（g6a 抽取，最后一本，追加确认同一模式）

### D11. 折线统计图/分数运算等内容也存在"新版教材编排后移"现象，与 D10 同一模式，非漏抽
背景：g6a 抽取报告"分数运算、折线统计图在 g1a~g5a（新版序列）中全部找不到系统引入课时"，其中折线统计图这一条被标记为"疑似真的漏抽，建议核查"（区别于分数——分数的后移在 g6a 抽取时已通过检索确认）。
核实过程：检索全部已完成书籍的 `knowledge_points.json`，发现"折线统计图"确实存在——但只出现在**旧版**的 `g4b`（"折线统计图"）与 `g5b`（"复式折线统计图"）中，新版序列 g1a~g5a 里一条都没有；同时确认 g6a 本书自己新引入了"折线统计图的认识（复现）"等 4 个统计图相关知识点。
结论：与 D10（面积后移到五年级）是**同一种现象**——本套新版教材（2022课标）把统计图（含折线统计图）的系统学习整体后移到了六年级集中处理，旧版教材（2011课标，g4b/g5b）是在四、五年级教的。不是抽取遗漏，是新旧版课标内容编排顺序的真实差异。g6a 知识点名里带"复现"二字是抽取时的合理保守标注（意识到这类内容按老版做法"应该"更早学过），本地知识点仍按规则新建，留给 Stage 2/5 处理版本间的合并与对齐。
影响：与 D10 一样，提醒 Stage 5 版本对齐、Stage 6 能力边界时不要用旧版教材的学习顺序作为默认预期；新版 g1a~g5a 的能力边界不应包含面积、折线统计图、系统性分数运算等内容，这些要等到 g5a（面积）/g6a（分数、统计图深化）才纳入。三次独立验证（D10 面积、D11 折线统计图与分数）后，这类"新版内容后移"已经是该教材的确定模式而非孤例，后续遇到类似"某常见小学知识点在前面几本新版书里找不到"的情况，应优先按这个模式核实，而不是默认当作漏抽处理。

## 2026-09-29　Stage 2~4 准备

### D12. DashScope 节点：北京为主、新加坡备用；客户端改为可配置 base URL + 连接复用
背景：云端执行环境换到专属工作空间节点（北京 `cn-beijing.maas`、新加坡 `ap-southeast-1.maas`，OpenAI 兼容模式），原客户端把公共域名 `dashscope.aliyuncs.com` 写死。实测两节点（4 模型 × 思考/非思考、16 并发 × 48 条成对判定式提示词）全部 200、无 429；延迟基本相当（非思考单次中位数 2.0～2.8s，deepseek-v4.1-flash 吞吐新加坡 7.2 条/s 略高于北京 5.8 条/s，qwen3.8-flash 两边均约 5 条/s）；纯网络往返约 0.8～1.1s，其中 TLS 握手约 0.55～0.8s。
决策：(1) 主节点读 `DASHSCOPE_BASE_URL` + `DASHSCOPE_API_KEY`（北京），可选备用节点 `DASHSCOPE_INTL_BASE_URL` + `DASHSCOPE_INTL_API_KEY`（新加坡），仅在网络错误 / 429 / 5xx 时切换；(2) 每个工作线程持有一个 `requests.Session` 复用 TLS 连接；(3) 缓存键不含节点。
理由：两节点性能差距小，客户端价格表按国内人民币定价，与北京账号计费一致，以北京为主可保证费用统计不失真；两节点是独立账号、限流额度独立，备用切换提高大批量标注的鲁棒性。连接复用省去每次约 0.6s 握手。缓存键不含节点是因为两节点提供同一模型，结果按内容可复现即可，节点只是传输通道。

## 2026-09-29　Stage 2 实体消解

### D13. 模型分工、`extends` 边类型与「判定冲突」约束
1. **模型分工（Stage 2/3/4 通用）**：流水线判定/生成统一用 `qwen3.7-plus`（非思考模式）；金标首轮盲标 `qwen3.8-flash` + `deepseek-v4.1-flash`（非思考，不同厂商），仲裁 `qwen3.8-max`（思考模式）。依据：实体消解试标 30 对，7 种配置与 Agent 独立参照标注的一致度——修订指南后 qwen3.8-flash 30/30、deepseek-v4.1-flash 29/30、qwen3.8-max 思考 29/30、qwen3.7-plus 非思考 28/30 / 思考 28/30；两个 flash 模型开思考模式没有提升（28～29/30）而费用高 40～60%，故首轮用非思考。流水线模型不进入任何标注模型组（CLAUDE.md 4.3.7）。流水线不用 Agent 自己判定，是因为 3685 个候选对 + 上千个题型卡片的量级用 API 更可复现（缓存重放）且成本低（全部约数十元）。
2. **试标发现的指南歧义**：初版指南下，所有模型都把「等量关系 → 方程的意义」「两步混合运算 → 运算律推广到小数」判为 `extends`，混淆了「B 需要用到 A」（前置，Stage 4 的事）与「B 是 A 的范围扩大」（螺旋扩展）。指南增加「『B 要用到 A』不等于 extends」一条及正反例后，分歧消失。
3. **`EdgeType.EXTENDS`**：任务书要求产出 `Edge(type=extends)`，原枚举无此值，新增。方向为「窄 → 宽」（`narrower` 由判定模型给出）。它是 Stage 4 前置判定的证据，不直接等同于 `builds_on`。
4. **判定冲突约束**：KICKOFF 只规定「同一课时内刻意区分的知识点不得合并」。v1 只用该约束时，出现 5 元簇（g3a 小数加减进退位 + g4b/g5a 的「位数相同」「位数不同」四个点），原因是传递性：各条 same 边单看都合理，但 g4b 内部刻意区分的「位数相同」与「位数不同」被链到一起，而判定模型对这一对本身直接判的是 extends。val 上聚类后 same 精确率只有 0.79（判定级 0.88）。于是把「判定模型直接判为 extends/different 的候选对」也加入 cannot-link：直接判定是比传递推出的「同一」更强的证据。聚类后 same 精确率 0.79 → 0.91、召回 1.0 → 0.95、F1 0.88 → 0.93，最大簇 5 → 3。未采用「同一本书内的知识点一律不得合并」这一更粗的规则：它没有被观测到的必要，且会挡住同书内确属重复的抽取（如 g1b 两个课时各建了一次的「平面图形的认识」）。
5. **规范知识点属性**：以教学序列中最早引入的成员为主成员（名称、领域、主线、描述取自它），引入课时取最早者，其余成员的引入/复现课时并入复现课时，别名/典型错误/显式引用取并集，`grants` 按半格合并（数值取 max、集合取并）。课时的 `intro` 只保留「规范知识点首次引入于本课时」者，其余改记为 `practice`（新旧版重复教学自然成为复现，即 KICKOFF Stage 5 第 1 步）。规范 ID 沿用主成员的局部 ID；局部 ID 跨书重名但未合并时追加 `_书ID` 消歧。

### D14. 「长方形/正方形面积」「面积单位」在 12 本书中都没有引入——版本缺口，修正 D10 的表述
背景：生成检索探针金标时，「三年级周长面积」一类需求找不到长方形面积知识点。复核 g5a「多边形的面积」单元：平行四边形面积靠「转化为长方形」推导，单元练习含面积单位换算（m²），即**默认学生已会长方形面积与面积单位**；但新版 g3b / g4a 与旧版 g4b 中都没有这两个知识点（旧版教材把面积放在三年级下册，而我们手上的三下是新版；新版四年级下册无法获取）。
结论：这不是 Stage 1 漏抽，而是版本混杂造成的**缺口**（KICKOFF Stage 5「缺口补全」的典型情形）。D10「面积后移到五年级」的表述不准确：五年级学的是多边形面积，长方形面积与面积单位应在五年级之前，只是现有 12 本书都没有覆盖。
影响：Stage 5 须为「面积与面积单位」「长方形和正方形的面积」补建 `reconciled` 知识点（引入位置按前置约束定在 g5a 之前）；检索探针中涉及三年级面积的条目（p08、p35、p47）的金标在补全后需要复核更新。Stage 2～4 不做处理（不在下游打补丁）。

## 2026-09-29　Stage 4 关系推断

### D15. 候选生成增加第三路「模型筛选」
背景：评测先行，Stage 4 金标生成后、流水线判定前，先在 val 锚点金标上测候选召回。KICKOFF 的两路（同主线/同主题时间约束 + 共现，再并上 Stage 2 的 extends）召回只有 122/147 = 0.83（阈值 0.95）。漏掉的全是跨主题、跨领域的前置：「10以内加减法」→「总量与分量的关系」（数与运算 → 数量关系）、「千米的认识」→「速度、时间与路程的关系」（图形与几何 → 数量关系）、「比的基本性质」→「图形的放大与缩小」等。
决策：增加第三路——对每个知识点 B，流水线模型 qwen3.7-plus 看 B 的完整信息与全部 419 个知识点清单，挑出可能的直接前置（宁多勿漏），作为候选，仍须经逐对判定。419 次调用，产出 1738 个候选对，其中 513 对是新增的。
效果：val 候选召回 0.83 → 0.993（146/147）。消融检验：若同时去掉「同主题时间约束路」（19,527 对，占候选的 88%），召回降到 0.837——筛选路与同主题路各自覆盖对方漏掉的前置，两路都保留。
替代方案：把时间约束路扩大到「同领域跨主题」会让候选从 2.2 万对增至约 4 万对以上，但仍覆盖不了跨领域的前置（千米 → 速度路程），故不采用。

### D16. 低置信度「前置」降级为 builds_on（阈值 0.95），不采用思考模式
背景：v1 全量判定 22,088 个候选，5,222 对判为 prerequisite（24%，平均每个知识点 12.5 条前置边）。val 上闭包 F1 0.807（勉强过 0.80），但精确率只有 0.70：(1) 金标为 builds_on 的递进关系几乎全被判成 prerequisite（流水线从不输出 builds_on）；(2) 少量错误直接边在传递闭包上放大，连「非候选」层都有 4/25 对因链条变成可达。
试验：(a) 流水线开思考模式重判 val 候选：假阳性 10 vs 11，召回反降（41 vs 44 个真前置），无改进且费用翻倍，不采用。(b) 置信度：val 上 11 个假阳性前置判定置信度全部 ≤ 0.9，真前置多为 0.95～1.0。
决策：判定为 prerequisite 且置信度 < 0.95 的，边类型记为 builds_on（语义：有递进依赖，但不能确定是否严格必需），原始判定标签与置信度写入 `evidence.judged_label / judged_confidence`，判定记录本身不改。
效果（val）：前置边 5,222 → 3,588，闭包 P 0.70 → 0.95、R 0.96 → 0.75、F1 0.807 → 0.837；锚点闭包召回 0.98 → 0.76；与教学顺序相反的前置边 13 → 2。
取舍理由：前置边的假阳性对下游伤害更大——Stage 5 会为每条逆序前置边前移知识点的引入位置，假前置直接导致不必要的 `reconciled` 修复；被降级的边仍以 builds_on 保留，螺旋复习所需的依赖信息不丢失。召回下降在汇报中如实说明，阈值在 test 上复核。

### D15 补充（同日）. 反向筛选；旧 test 锚点降级为开发集
- test 验收时候选召回为 0.90（val 0.993）：val 上的高分偏乐观，因为第三路正是照着 val 的漏召回设计的。为了不在 test 上调参，把旧 test 锚点降级并入开发集，另外新抽 100 个从未用过的锚点，按同样的两步法标注，作为新的验收集（新验收集第 2 步逐对判定的 5 类 κ = 0.56，「是否前置」二元 κ = 0.67；分歧主要在 builds_on/prerequisite 边界，停顿点人工核验重点抽查）。
- 开发集（205 个锚点，261 个金标前置对）上的 12 个漏召回全部是**同领域跨主题**（10 个是「数与运算 → 数量关系」）。两个方案对比：把时间约束路扩大到同领域要新增 17,817 对候选，召回 0.954 → 0.977；**反向筛选**（对每个 A，流水线模型从全表挑出直接依赖 A 的知识点）只新增 551 对，召回 0.954 → 0.973。采用反向筛选，成本相差 30 倍以上。
- 新验收集上：候选召回 **0.981** [0.956, 0.992]，闭包 F1 0.828。

### D17. 「总复习」类伞形知识点作起点的前置边记为 related
反向筛选引入了一批「图形的测量（总复习）→ 圆柱的体积」「运算律（总复习）→ 整数运算律在分数运算中的应用」之类的前置边（10 条，判定置信度 ≥ 0.95），方向是反的：总复习知识点汇总已学内容，依赖具体知识点，而不是它们的前置。这是判定模型在伞形知识点上的系统性弱点。用确定性规则处理：起点为「总复习 / （复习）」伞形知识点的 prerequisite / builds_on 边一律记为 related，原始判定保留在 `evidence.judged_label`。与教学顺序相反的前置边 21 → 11，剩下的（如「小数数位的计数单位 → 小数加减法中的进位与退位」「整数除以分数 → 分数除法的一般法则」）是 Stage 5 要处理的真实顺序信号。未改判定提示词重判全部 2.2 万对：这条规则针对的错误清楚、可解释，重判约 90 元。

## 2026-09-29　Stage 3 题型归纳

### D18. 题型卡片的程序校验逐步加严；生成改为逐张推进
1. **试跑暴露的偏差**（13 个题型的小规模试跑）：模型会为了能被程序校验而改变题目的考查方式——画图题改成填空题、选择题不给选项却写答案「A」、把多种题拼成一道大题。提示词加上「保持源实例的题目形式与考查方式」「一个题型只写一种题」，并按源实例的真实性质判定可验证类型；改后画图题保持为 rule、说理题保持为 human。
2. **校验项**：V1 示例答案 = 程序重算（数值等价，支持列表/字典）；V2 在槽位约束内随机采样 20 组，求解程序可运行、非浮点、满足约束；V3 槽位不超出教材观测包络（整数位数、小数位数）；V4 示例与源实例原文字符 5-gram 重合率 < 0.5；V5 题面含数值参数；V6 示例互不相同。
3. **采样器与约束接受率**：首次全量运行后剩下的失败里，有 5 个是采样器的问题而不是卡片的问题（两个「10 的倍数」约束同时成立的概率只有 1/100，200 次尝试不够）→ 尝试次数提到 5000，int 槽位支持 `step`。随后评测用的生成探针（种子与校验不同）又发现 3 个、之后 1 个题型换种子就采不到——约束接受率极低（如「营业额能被单价整除」对三本书同时成立，约 0.15%）。先把 V2 改为 3 个种子都通过，仍漏 1 个；最终增加 **V2a 约束接受率 ≥ 1%**（随机抽 2000 组统计），并提示模型把受约束的量写成计算结果（采样单价与数量，营业额 = 单价 × 数量）。V2a 一次性筛出 56 张侥幸通过的脆弱卡片送回修复。
4. **修复流程**：最多 6 轮，第 3 轮起用思考模式；第 4 轮起反馈中附常见错误提醒（禁用 float、参数名与槽位一致等）。沙箱剔除 `from fractions import Fraction` 这类无害导入（所需名字已提供），其余 import 仍禁止。
5. **逐张推进**：按轮次整批等待时，第 3、4 轮各花 18～21 分钟等最慢的一两个思考请求。改为每张卡片独立推进（生成 → 校验 → 修复），每轮提示词与整批方式逐字相同，缓存照样命中；思考请求单次超时 300 秒、最多重试 1 次，失败交给下一轮，不再拖住整批。
