## 1. 数据来源与版本

输入是北师大版小学数学 12 册教材 PDF（`g1a`～`g6b`），只读、不入库。

### D1. `ExerciseInstance.text` 保存习题原文；改写示例必须新写

`ExerciseInstance` 带 `text` 字段，存单题粒度的习题原文（图形部分用文字描述配图内容）。`ItemArchetype.rewritten_examples` 则必须依据模板与参数约束重新生成，不得复述或改编任何一条 `text`。

理由：(1) 标注模型组看到原文，能显著提升实体消解、题型粒度等标注数据的质量；(2) 改写示例要作为生成环节的参考范式，必须是经过模板与参数约束校验的新题，而不是教材原题的存档，这与是否存原文无关。

版权边界：`data/` 与 `work/books/*/exercises.json` 含约四千条单题粒度的文字摘录（不含整页版式与插图），随公开仓库发布，用于教学研究。整页渲染图、整页 OCR 文本、页面截图一律不入库，只能存在于 `tmp/`，处理完即删。

### D5. 版本边界按年级而非按学期：9 本新版 + 3 本旧版

逐本核对封面审核章与后记：

| 版本 | 依据 | 册 |
|---|---|---|
| 新版 | 2022 年版课标；国家教材委员会专家委员会审核通过（2024） | `g1a g1b g2a g2b g3a g3b g4a g5a g6a`（9 册） |
| 旧版 | 2011 年版课标；教育部审定（2013） | `g4b g5b g6b`（3 册） |

这与"新课标逐年级滚动换版、四至六年级下册尚未跟进"的现实一致。含义：版本对齐的工作集中在 `g4b/g5b/g6b` 与其余 9 册之间，尤其是 `g3b→g4a→g4b→g5a`、`g4b→g5a`、`g5b→g6a` 这些跨版本衔接处（见 §6）。

### D10. 新版教材编排后移：「面积」在 g1～g4 中缺失

`g1a`～`g4b` 共 8 册的知识点全文检索没有任何面积知识点，唯独教过周长。核实：`g3b`（新版）目录有「周长」单元而无「面积」单元；`g4a` 的「图形的奥秘」讲立体图形截面与空间想象，不含面积测量。结论：这不是抽取遗漏，而是新版把面积的系统学习编排到了五年级上册（`g5a`），与传统"三年级学周长和面积"的顺序不同。

后果：新版 `g1a`～`g4a` 的能力边界不应含面积相关能力。下游遇到"某常见知识点在前面几册新版里找不到"时，应先按"内容后移"核实，而不是默认当作漏抽（该结论的细化见 D14）。

### D11. 折线统计图、分数运算同样后移

「折线统计图」只出现在旧版 `g4b`（折线统计图）与 `g5b`（复式折线统计图）中，新版 `g1a`～`g5a` 一条也没有；`g6a` 自己新引入了统计图相关知识点（含"折线统计图的认识（复现）"）。分数运算的系统学习同样后移到 `g6a`。与 D10 是同一种现象：新版把统计图整体后移到六年级集中处理，旧版则在四、五年级教。

后果：新版 `g1a`～`g5a` 的能力边界不含面积、折线统计图、系统性分数运算；`g6a` 中以"复现"命名的知识点是抽取时的保守标注，仍按规则新建，由实体消解与版本对齐处理跨版本合并。D10、D11 与 D14 构成三次独立验证，"新版内容后移"是该教材的确定模式。

### D14. 「长方形/正方形面积」「面积单位」是 12 册的真实缺口（修正 D10）

`g5a`「多边形的面积」单元用"转化为长方形"推导平行四边形面积，单元练习含面积单位换算，即默认学生已会长方形面积与面积单位；但新版 `g3b`/`g4a` 与旧版 `g4b` 都没有这两个知识点（旧版把面积放在三年级下册，而现有的三下是新版；新版四年级下册不在 12 册之内）。

因此 D10 应读作：五年级学的是多边形面积，长方形面积与面积单位应在五年级之前，只是现有 12 册没有覆盖。这是版本混杂造成的**缺口**，由 Stage 5 补建（D22/D23）；同时，涉及"三年级面积"的检索探针（p08、p35、p47）标注数据在补全后重标（D27）。检索的年级先验因此设计为软先验（D20）。

## 2. 抽取与数据模型

### D6. 无文字层的书：渲染后读图，不用 OCR

`g4b` 全书无文字层。在抽取前，用 150 DPI 渲染两页典型内容页（含刻度尺与分数/小数对照的「小数的意义（二）」、含小数加减混合运算竖式的「歌手大赛」），分别用多模态读图和 tesseract（`chi_sim`）处理。

结论：读图能准确识别全部文字、算式、竖式、分数记号与图形要素（刻度尺读数、天平/电子秤示数），OCR 的错误密集且集中在关键数值和专名上，例如 `8.65+0.40=9.05` 的 "9.05" 被识别成 "4.05"，`9.43-(8.65+0.40)` 被识别成 "94.43- (365+040)"，"12克=(　)千克" 的括号填空结构完全丢失。数值级错误看起来像合理数字，后续校验难以发现，会直接污染 `text` 与 `operand_features`。因此对无文字层的书一律渲染后读图；OCR 只可用作文字密集页的辅助定位，不用于核对数值。

曾考虑"OCR + 读图双重核对"，因 OCR 错误率过高、核对成本接近重读，对 9 个单元的体量不划算而放弃。有文字层的书（6 册 "a" 书）用 PyMuPDF 抽取文字，装饰字体标题（目录页等）可能乱码，改用渲染图核对。tesseract 5.5.3（含 `chi_sim`）保留在 `environment.yml` 中，用于上述辅助定位。

### D7. `ExerciseInstance` 的拆分规则：只看编号，不看内容条数

有独立小题号（(1)(2)(3)、①②③ 等）就拆成多条实例；没有编号的批量算式、填空、判断题，无论列了几项，整体记为 1 条，`text` 完整列出全部内容，`operand_features` 按整组的典型特征填写。选择"看编号"作为唯一信号，是为了去掉"是否共享数据""是否为展示规律而分组"这类更细的例外，降低不同抽取者之间的判断分歧。

### D8. 跨年级前置知识：在本书内建为正式知识点

本书内找不到可挂靠的、明显是低年级已学的内容（复习课里出现的"探索规律""图形分类"等），在本书内新建为正式的局部知识点，而不是临时占位标记，交给实体消解（§3）去与其他书的对应知识点合并。这与抽取指南"拿不准时倾向于分开记录"的原则一致，不需要额外的占位标记体系。

### D9. 图形信息判读不清：如实标注，不二次渲染

无法判读的图形信息（算盘珠子、身份证号等）在 `text` 中如实注明"未能判读"，不编造数值，也不用更高 DPI 重新渲染核实。默认的 120～150 DPI 对绝大多数页面已足够；未能判读的实例为 4319 条中的 11 条（0.25%），不影响下游使用，成本收益不划算。

## 3. 实体消解

12 册各自抽取出 466 个局部知识点，需要合并为规范知识点（433 个中的 419 个来自教材）。

### D13. 成对判定模型分工、`extends` 边与「判定冲突」约束

1. **模型分工（Stage 2/3/4 通用）**：流水线判定与生成统一使用 `qwen3.7-plus`（非思考模式）；标注数据首轮盲标用 `qwen3.8-flash` 与 `deepseek-v4.1-flash`（不同厂商，非思考），仲裁用 `qwen3.8-max`（思考模式）。依据：对 30 对实体消解样本，7 种配置与独立参照标注的一致度——指南修订后 `qwen3.8-flash` 30/30、`deepseek-v4.1-flash` 29/30、`qwen3.8-max` 思考 29/30、`qwen3.7-plus` 非思考 28/30 / 思考 28/30；两个 flash 模型开思考模式没有提升（28～29/30）而费用高 40～60%，故首轮用非思考。流水线模型不进入任何标注模型组（独立性原则，见 §9）。流水线用 API 而不是人工判定，是因为 3685 个候选对加上千个题型卡片的量级，用 API 更可复现（缓存重放）且成本低。
2. **标注指南的一处关键界定**：初版指南下，所有模型都把「等量关系 → 方程的意义」「两步混合运算 → 运算律推广到小数」判为 `extends`，混淆了「B 需要用到 A」（前置，Stage 4 的事）与「B 是 A 的范围扩大」（螺旋扩展）。指南增加「"B 要用到 A"不等于 extends」一条及正反例后，分歧消失。
3. **`EdgeType.EXTENDS`**：成对判定的三分类（`same` / `extends` / `different`）需要一种边来承载"螺旋扩展"，故数据模型有 `extends` 边，方向为「窄 → 宽」（`narrower` 由判定模型给出）。它是 Stage 4 前置判定的证据，不等同于 `builds_on`。
4. **判定冲突约束**：只用"同一课时内刻意区分的知识点不得合并"一条约束时，会出现 5 元簇（`g3a` 小数加减进退位 + `g4b/g5a` 的「位数相同」「位数不同」），原因是传递性：各条 `same` 边单看都合理，但 `g4b` 内部刻意区分的「位数相同」与「位数不同」被链到一起，而判定模型对这一对直接判的是 `extends`。因此把"判定模型直接判为 extends/different 的候选对"也加入 cannot-link：直接判定是比传递推出的"同一"更强的证据。开发集聚类后 `same` 精确率 0.79 → 0.91、召回 1.0 → 0.95、F1 0.88 → 0.93，最大簇 5 → 3。曾考虑"同一本书内的知识点一律不得合并"这一更粗的规则，因没有被观测到的必要，且会挡住同书内确属重复的抽取（如 `g1b` 两个课时各建了一次的「平面图形的认识」）而放弃。
5. **规范知识点属性**：以教学序列中最早引入的成员为主成员（名称、领域、主线、描述取自它），引入课时取最早者，其余成员的引入/复现课时并入复现课时，别名/典型错误/显式引用取并集，`grants` 按半格合并（数值取 max、集合取并）。课时的 `intro` 只保留"规范知识点首次引入于本课时"者，其余改记为 `practice`（新旧版重复教学自然成为复现）。规范 ID 沿用主成员的局部 ID；局部 ID 跨书重名但未合并时追加 `_书ID` 消歧。

## 4. 题型归纳与校验

教材 4319 道习题归纳为题型卡片（抽象模板 + 槽位约束 + 求解程序 + 可验证类型 + 难度 + 改写示例）。当前共 2068 个题型：2009 个来自教材习题，49 个为缺口知识点补建（D26），10 个为无主习题的知识点补建（D32）。

### D18. 题型卡片的程序校验

1. **保持考查方式**：模型倾向于为了让题能被程序校验而改变题目的考查方式（画图题改成填空题、选择题不给选项却写答案「A」、把多种题拼成一道大题）。提示词因此要求"保持源实例的题目形式与考查方式""一个题型只写一种题"，并按源实例的真实性质判定可验证类型；画图题保持为 `rule`，说理题保持为 `human`。
2. **校验项**：V1 示例答案 = 程序重算（数值等价，支持列表/字典）；V2 在槽位约束内随机采样 20 组，求解程序可运行、非浮点、满足约束；V2a 约束接受率 ≥ 1%（随机抽 2000 组统计）；V3 槽位不超出教材观测包络（整数位数、小数位数）；V4 示例与源实例原文字符 5-gram 重合率 < 0.5；V5 题面含数值参数；V6 示例互不相同。
3. **采样器与约束接受率**：「两个 10 的倍数约束同时成立」的概率只有 1/100，因此采样尝试上限为 5000 次，`int` 槽位支持 `step`。约束接受率极低的卡片（如「营业额能被单价整除」对三本书同时成立，约 0.15%）会让评测探针换个种子就采不到样，故引入 V2a，并提示模型把受约束的量写成计算结果（采样单价与数量，营业额 = 单价 × 数量）。V2a 一次性筛出 56 张侥幸通过的脆弱卡片送回修复。
4. **修复流程**：最多 6 轮，第 3 轮起用思考模式，第 4 轮起反馈中附常见错误提醒（禁用 float、参数名与槽位一致等）。修复轮次用尽仍未通过的，如实降级为 `human`（不带求解程序），保证实例有归属；教材题型中此类共 5 个。
5. **逐张推进**：每张卡片独立推进（生成 → 校验 → 修复），每轮提示词与整批方式逐字相同，缓存照样命中；思考请求单次超时 300 秒、最多重试 1 次，失败交给下一轮，不拖住整批。
6. **沙箱**：求解程序在子进程沙箱中运行，剔除 `from fractions import Fraction` 这类无害导入（所需名字已提供），其余 import 仍禁止。子进程用 UTF-8（`-X utf8`；`-I` 隔离模式会忽略 `PYTHON*` 环境变量），避免 Windows 默认 gbk 编码使含「✓」等字符的题面崩溃。

### D26. 题型分组：(主知识点, 形式) 内的语义细分

**采用的方案**：先按 (主知识点, 题目形式) 分组（1179 组，其中 374 组只有 1 个实例）；对含 ≥ 2 个实例的组，用流水线模型 `qwen3.7-plus`（非思考，D13）读全部实例原文与答案形式，按「考什么 / 怎么答 / 解法思路」划分子组，一个子组一个题型。拆分的依据是作答方式大类（计算求值 / 画图操作 / 判断选择 / 读图读表 / 开放表达，其中开放表达再分解释说理 / 创编提问 / 探究实践）、正向求值与逆向求条件、一步直接算与多步综合、应用题里不同的数量关系模型；**不拆**数的大小、位数、有无进退位、情境、措辞、次要知识点（它们仍进入参数包络）。无回退、无挂靠：单实例子组就是单实例题型。每次判断以 Judgment 落盘（`work/judgments/stage3_partition.jsonl`）。

**取代的方案（v1）**：签名 =（主知识点、形式、次知识点集合、操作数粗分桶），单实例组逐级回退到更粗层级再挂靠到最近题型。v1 的失败原因：对粒度标注数据的 val 上 26 个"过粗"逐条归类，几乎全部是同一 (主知识点, 形式) 组里混了作答方式不同的题（计算 vs 说理 vs 画图 vs 连线；形式为 `other`/`word_problem` 的组尤其多），少数是正向 vs 逆向、一步 vs 多步；数字特征分不出这些差别，回退又把不同类的单实例并进来。

**粒度指南 v2**：诊断发现粒度标注数据本身有漂移——标注模型拿抽象模板对比源题而不是源题互比，且几乎不判"过细"。指南 v2 改为只比较源实例（组内互比判过粗，与同知识点其他题型的源实例比较判过细，不评判模板），补充 `too_fine` 正反例与边界规则（差别只在参数不算混杂；单实例内含多问按主问判），标注材料里不再给模板。用 v2 指南重标 v1 方案的同一批 150 个题型，test"合适"0.44 → 0.61：指南修订本身解释了约 0.17 的提升，其余差距来自分组方案。此后"改进前后"只用指南 v2 下的数字比较。

**提示词迭代**（只用 val 抽样评估，卡片建立之前，test 不参与）：第一版"宁合勿拆"无具体标准，压缩率 1.91，模型把同为开放表达的题拆成三个；第二版给出作答方式大类并规定开放表达不再拆，压缩率 2.36、val 合适 0.78，剩余过粗集中在开放表达内部与应用题的数量关系模型；第三版（定稿）把开放表达再分三类并加入"应用题里数量关系模型明显不同要拆"，压缩率 2.15、val 合适 0.89。已达标，没有继续细化（再改会碎得更多）。

**结果**（指南 v2 标注数据，详见 `eval/specs/stage3.md`）：粒度"合适"val 0.892 [0.801, 0.944]、test 0.863 [0.766, 0.924]；压缩率 2.15；单实例题型 1042 个（占教材题型 51.9%，数据下限 18.6%）。

**阈值**：粒度"合适"占比的阈值由无数据时的先验 0.85 调整为 0.80，并规定"一轮改进后 ≥ 0.70 且边际收益下降即停"：细分越积极，单实例长尾碎片越多，不宜无限追求更高的合适占比。指标定义（合适占比）未变。

**单实例门槛**：原门槛"单实例题型超出数据下限的占比 ≤ 0.05"对 v2 不适用——v2 的单实例子组大多是"同组内明显不同类"的实例（超出下限 0.33），硬压会把不同类的题重新合并，回到过粗。真正要防的是过细的长尾碎片，因此改为直接度量：单实例题型被粒度标注数据判为过细的比例 ≤ 0.10（test 0.025 [0.004, 0.129]，n=40，通过）。单实例占比与超出下限继续报告。

**增量重生成**：对实例集合与上一版某题型完全相同的题型，复用 `data/archetypes.json` 里已通过校验（或已如实降级）的卡片（629 个），只为其余 1380 个生成卡片，校验与修复沿用 D18；6 轮修复后各轮进入数 {1:1380, 2:468, 3:234, 4:60, 5:17, 6:8}，降级为 `human` 的 5 张。情境库与表述规范沿用已落盘的 `data/contexts.json`、`data/glossary.json`（重跑会产生不同的归并），题型的 `allowed_contexts` 由"实例 ID → 情境"反查。

**缺口题型**：Stage 5 补建的 14 个缺口知识点没有教材习题，按「知识点 × 建议方向」当虚拟分组，复用 `generate_cards`（D18 全部校验），共 49 个题型，`provenance=reconciled`、`source_instance_ids=[]`，参数包络按引入年级取保守上限（整数位数 ≤2/3/4/6/6/8 对应 1–6 年级，小数位数 ≤2〔≤4 年级〕/ ≤3）。`build.run` 重建教材题型时原样保留这些题型。不变量对 `reconciled` 题型放宽"必须有源实例"，其余（程序重算、情境引用、5-gram）不放宽。下游注意：这些题型没有源实例所在课时，边界探针应取主知识点的引入课时。

**难度**：由可解释特征（解题步数、知识点数、主次知识点引入位置的跨度、是否逆向思考、是否读图）标准化加权，在年级内按分位数映射为 1～5；引入位置变动后用 `python -m chalkbase.stage5 difficulty --write` 重算。分数相同取同一等级，故各等级数量不均（1:616, 2:274, 3:717, 4:88, 5:373）。

### D32. 每个可考查知识点至少有一个题型

428 个可考查知识点中有 10 个（如「10的认识」「平均分的认识」「有余数的平均分」）没有题型：它们在教材里有对应课时，但抽取时把相关习题挂在了相邻知识点下（主知识点实例数为 0，次知识点 ≤4），按实例分组自然产不出卡片，下游"按知识点出题"会在这些点上落空。

做法：复用缺口卡片流程（`python -m chalkbase.stage3.gaps uncovered`）为这 10 个知识点按描述各生成 1 个题型（`provenance=reconciled`，无源实例，D18 校验全部适用：8 个 `program`、2 个 `rule`），并新增不变量 `test_every_assessable_kp_has_an_archetype`。不回头改抽取阶段的挂载：这 10 个点的实例本就分散在相邻知识点下，重新拆分会动摇已冻结的下游产物，且收益只是这 10 个点。

## 5. 关系推断

对规范知识点推断前置（`prerequisite`）、递进（`builds_on`）、相关（`related`）、易混淆（`confusable`）。核心判定问题是"不掌握 A，学生能否学会 B"；判定不受教材编排顺序影响，与教学顺序相反的前置边如实输出，交给 Stage 5。

### D15. 候选生成：时间约束路 + 共现路 + 模型筛选路（正向与反向）

两路确定性候选（同主线/同主题时间约束路 + 次知识点共现路，并上 Stage 2 的 `extends`）在开发锚点标注数据上的召回只有 122/147 = 0.83（阈值 0.95）。漏掉的全是跨主题、跨领域的前置：「10以内加减法」→「总量与分量的关系」（数与运算 → 数量关系）、「千米的认识」→「速度、时间与路程的关系」（图形与几何 → 数量关系）、「比的基本性质」→「图形的放大与缩小」等。

**第三路：模型筛选。** 对每个知识点 B，流水线模型看 B 的完整信息与全部知识点清单，挑出可能的直接前置（宁多勿漏）作为候选，仍须经逐对判定。开发集候选召回 0.83 → 0.993。消融：若同时去掉时间约束路（占候选的 88%），召回降到 0.837——两路各自覆盖对方漏掉的前置，都保留。曾考虑把时间约束路扩大到"同领域跨主题"，候选会从 2.2 万对增至约 4 万对以上，仍覆盖不了跨领域的前置，放弃。

**反向筛选与验收集更换。** 0.993 是照着开发集的漏召回设计出来的，偏乐观：在原 test 验收时候选召回为 0.90。为避免在 test 上调参，旧 test 锚点并入开发集，另外新抽 100 个从未用过的锚点，按同样的两步法标注为新验收集（5 类 κ = 0.56，"是否前置"二元 κ = 0.67；分歧主要在 `builds_on`/`prerequisite` 边界）。开发集锚点上的 12 个漏召回全部是同领域跨主题（10 个是"数与运算 → 数量关系"）。两个方案对比：把时间约束路扩大到同领域，新增 17,817 对候选，召回 0.954 → 0.977；**反向筛选**（对每个 A，让流水线模型从全表挑出直接依赖 A 的知识点）只新增 551 对，召回 0.954 → 0.973。采用反向筛选，成本相差 30 倍以上。新验收集上候选召回 **0.981** [0.956, 0.992]。

### D16. 低置信度「前置」降级为 `builds_on`（阈值 0.95），不用思考模式

全量判定 22,088 个候选，5,222 对判为 `prerequisite`（24%，平均每个知识点 12.5 条前置边）。开发集上闭包 F1 0.807，但精确率只有 0.70：(1) 标注数据为 `builds_on` 的递进关系几乎全被判成 `prerequisite`；(2) 少量错误直接边在传递闭包上放大。

- 流水线开思考模式重判：假阳性 10 vs 11，召回反降（41 vs 44 个真前置），费用翻倍，无改进，不采用。
- 置信度：11 个假阳性前置判定的置信度全部 ≤ 0.9，真前置多为 0.95～1.0。

做法：判定为 `prerequisite` 且置信度 < 0.95 的边类型记为 `builds_on`（有递进依赖，但不能确定是否严格必需），原始判定标签与置信度写入 `evidence.judged_label / judged_confidence`，判定记录本身不改。效果（开发集）：前置边 5,222 → 3,588，闭包 P 0.70 → 0.95、R 0.96 → 0.75、F1 0.807 → 0.837；与教学顺序相反的前置边 13 → 2。

取舍：前置边的假阳性对下游伤害更大——Stage 5 会为每条逆序前置边前移引入位置，假前置直接导致不必要的 `reconciled` 修复；被降级的边仍以 `builds_on` 保留，螺旋复习需要的依赖信息不丢。召回下降如实报告，阈值在 test 上复核。

### D17. 「总复习」类伞形知识点作起点的前置边记为 `related`

反向筛选引入了一批「图形的测量（总复习）→ 圆柱的体积」「运算律（总复习）→ 整数运算律在分数运算中的应用」之类的前置边（10 条，置信度 ≥ 0.95），方向是反的：总复习知识点汇总已学内容，依赖具体知识点，而不是它们的前置。这是判定模型在伞形知识点上的系统性弱点。用确定性规则处理：起点为「总复习 / （复习）」伞形知识点的 `prerequisite` / `builds_on` 边一律记为 `related`，原始判定保留在 `evidence.judged_label`。与教学顺序相反的前置边 21 → 11，剩下的是 Stage 5 要处理的真实顺序信号。没有为此改判定提示词、重判全部 2.2 万对：这条规则针对的错误清楚、可解释，重判约 90 元。

## 6. 版本对齐与缺口补全

Stage 5 处理三类版本问题：重复（由实体消解处理）、顺序冲突、缺口，并对前置子图做传递约简。入口 `python -m chalkbase.stage5`，幂等；只对 `prerequisite` 边施加自洽约束。

### D22. 结果：0 个前移、14 个补全；缺口比顺序冲突重要得多

违反自洽条件（前置 A 的引入晚于 B）的前置边 11 条，分诊后全部不前移：10 条是 Stage 4 的判定错误（7 条起点是 `g4a` 整理性知识点「自然数的认识」，伞形/总结性概念被判成具体知识的前置，与 D17 同类），1 条（整数除以分数 → 分数除法一般法则；新旧版把"分数除法"排在 6 上/5 下）先分诊为版本冲突，但审阅判定"特例不是必需前置"，改为取消前置。"逆序前置边都是版本冲突"的假设不成立，所以不为凑出"前移"而硬前移；前移算法仍保留（单调、不动点、最小性不变量），只是本数据上没有触发。

缺口来自两路：逐知识点的「被假定已学而缺」枚举（419 次调用）与课标覆盖（133 条内容要求，修复前 109 条被判覆盖，覆盖率 0.82；补全与终审后 124 条覆盖 + 9 条不适用 = 100%）。D14 的两个种子缺口（长方形/正方形面积、面积单位）均被独立发现。更大的发现是分数：12 册中根本没有「分数的意义」，而 40 余个知识点以它为基础。补全的 14 个知识点包括面积单位、长方形和正方形的面积、分数的初步认识、分数的意义、同分母分数加减法、约分与最简分数等。传递约简后前置边 3751 → 直接边 852。

### D23. 缺口知识点的引入位置与前置边审阅

1. **位置规则**：不晚于最早的依赖者（含 `builds_on`，因为缺口的位置是"选择"出来的，不像教材既有位置是观测）、不晚于其课标学段最后一册书末尾、不早于自己的前置；无依赖者的放在学段末尾。曾考虑"放在最早的前置依赖者所在课时"，会把长方形面积放到 `g5a`（与三角形面积同课），与三年级学面积的现实不符，也与要给三年级检索探针补标注数据的目标冲突，故加入学段上限。`g4b` 末尾的挂载点 `g4b.u9.l03` 是「学期总结」课，只是第二学段末尾的占位，不是真实教学位置。
2. **缺口前置边**：缺口与现有知识点逐对判定（沿用 Stage 4 指南与 D16 的 0.95 阈值），缺口之间互判。Stage 4 的老问题再现：判定模型把「分数的初步认识」当作比例、反比例、解比例、百分数等的前置，扇出过大；审阅（严格按"直接必需"）否决了 26 条。互为前置的一对缺口（初步认识 ↔ 意义）在环检测中暴露，规则：学段较低者指向较高者；同学段两条都不保留。长思考的非流式请求偶发断连，故缺口汇总拆成"分组（短输出）+ 逐个定义"两步，不用单个长输出请求。
3. **审阅—重建闭环**：否决累积到 `work/judgments/stage5_review_rejections.json`，每次都从原始知识点/课时/边重新构建（日志与数据互相对得上），重建后的条目再审；首轮通过率 0.808（118/146，低于 0.90 阈值），末轮 0.982（109/111）。
4. **审阅者与已核实事实冲突的缺口，未采纳否决**：长方形/正方形面积、分数的意义（以及面积单位）。审阅者凭"北师大三下教过"的先验判为"不是缺口"，但 12 册知识点名称/描述的全文检索确认没有（D14）。保留并记录在 `reports/editions.md` 第 5 节。这是本阶段最大的判断风险：若实际使用的教材里这些内容在别处，应调整缺口知识点的引入位置或删除。

### D24. 课标覆盖：个别条目定案并附理由

课标覆盖清单（`config/curriculum_standard_2022.yaml`，133 条内容要求）的终审（`qwen3.8-max` 思考）对两个条目前后判定不一致，经复核定案并写在 `chalkbase/stage5/standard.py`（`NOT_APPLICABLE` / `MANUAL_COVERED`，每条带理由）：古代认识四季（纯文化背景，不适用）、选择面积单位估测面积（由面积单位缺口 + 估测长度 + 不规则图形面积估计联合覆盖）。清单"不适用"共 9 条，全部写明理由（过程性/素养性表述、纯历史文化），逐条见 `reports/editions.md` 第 4 节。缺口知识点的题型卡片见 D26（缺口题型）。

### D30. 流水线顺序与产物位置

## 7. 能力边界

能力边界 = 沿教学序列对各知识点 `grants`（能力增量）做半格单调折叠的结果，粒度是课时，7 个维度。

### D21. 受控词表、`grants` 补全与单调折叠

**背景**：抽取阶段的 `grants` 草稿极稀疏（433 个知识点中，整数上限 11 个、小数位数 3 个、分数类型 5 个、运算形态 55 个非空），且是自由文本（「两位数加两位数，进位」），校验函数无法确定性匹配。

**设计**：

1. **受控词表**（`chalkbase/boundary/vocab.py`）：整数数域与小数位数用整数；分数类型 5 个枚举（几分之一/几分之几/真分数/假分数/带分数，带蕴含闭包）；**运算操作数形态按运算各一张标签表**（加减法：整数/进位/退位/小数/位数不同/同异分母/带分数；乘除法：表内、乘数/除数位数的有序族、有余数、商为小数、小数与分数各形态），形态由**具体操作数确定性推出**（`derive_forms`，`Decimal`/`Fraction`），不靠语言模型；计量单位 = 规范名 + 别名表（㎡、m²、km/h → 规范名），日常时间单位（年月日周天）与计数单位不进词表；几何词汇 = 种子词表 + 开放扩充 + NFKC 规范化；概念 = 知识点名称/别名（自动授予）+ 补全时写入的短名词短语，规范化后精确匹配，词表外的概念记 `unknown`，不算越界。进位/退位采用教学口径（和 ≤10 的凑十、整十数相加 ≤100 不算进位；被减数 ≤10、整十数相减不算退位）；乘除数位数按**有效位数**（去掉末尾 0，230×400 按 23×4）。
2. **补全两路 + 覆盖修复**：①语义补全：`qwen3.7-plus` 非思考（D13）看知识点描述与引入课时的习题原文，在词表内填「新增能力」，每个知识点一条 Judgment（`work/judgments/stage6_grants.jsonl`）；乘/除数位数的高位标签必须有知识点名称/描述里的关键词支撑（语义补全曾把习题里顺带出现的算式当成新教的，例如把「连乘运算顺序」标成两位数乘法，导致 `g3b` 提前允许两位数乘两位数）。②数据驱动：教材实例的 `operand_features` + `text` 挖掘出的特征（只解析 `数 运算符 数` 二元片段并尊重优先级；单位/几何词汇只取有数字或括号前缀的形态、≥2 字、剔除泛用词；分数类型只在已判定涉及分数的实例里挖）作为观测证据，沿课时顺序折叠；实例所需能力不在当时边界内的缺口，补进**该课时引入的知识点**（优先实例的主/次知识点），该课时没有引入任何知识点则记入 `lesson_residual`（16 个课时）。概念维度的缺口（主知识点引入晚于使用它的实例）是引入位置问题，属于 Stage 5，只记录不修复。
3. **实例不变量的结果**："每个教材实例不超出所在课时边界"：仅用抽取草稿 `grants` 折叠时 69.9%（3019/4319）在边界内；仅语义补全 95.7%（4132/4319；分数基础知识点补全前为 89%）；覆盖修复后 100%，共修复 54 个实例（涉及几何词汇 32、运算形态 13、计量单位 11、整数 2、分数 1 个缺口），清单在 `work/stage6/repairs.json`。抽取错误 1 例：`ex.g4a.u12.l04.01` 把 18 位公民身份号码当成 18 位整数，豁免整数数域检查（`mine.NON_QUANTITY_INTEGER_INSTANCES`），未改动 `data/exercises.json`。
4. **折叠与存储**：`chalkbase/boundary/fold.py` 为纯函数（半格 max/并集，性质测试：同一课时内 `grants` 顺序无关、边界单调）；`data/boundaries.json` 对集合型维度存逐课时增量（全量约 11MB，增量约 0.18MB），`BoundaryStore` 读取时累加还原；引入位置只读 `data/knowledge_points.json` 的 `first_introduced_lesson_id`，Stage 5 改动后重跑 `python -m chalkbase.boundary build` 即可。
5. **越界探针的口径**：①规模为 7 维度 × 6 个年级 × 3 个课时的构造任务，共 240 题（≈每维度 34 题；开发集 114 / 验收集 125 条有效标注数据），而不是逐类 ≥15 条的配额；②两条链路：A = 构造者给出的标准特征直接喂 `check_item`（只测边界与校验函数），B = 抽取器从题面抽特征（端到端）；③标注者看到的上下文是「已学知识点名称 + 接下来才教的 25 个知识点名称」+ 题面（只给已学清单时，标注者无法识别"下一课时才教"的内容，把明显依赖未学知识点的题判为在范围内）；④教材里知识点的引入课时有 ±1～2 课时的模糊（同一单元相邻课时讲的常是同一类内容），所以除严格口径外同时报告容差口径与意图一致子集（构造意图与标注数据一致的条目，噪声较低），三种口径都报告，不以最好看的一个替代严格口径。
6. **局限**：严格口径下链路 A 查准/查全约 0.78/0.80。失败分析：(a) 标注数据噪声——仲裁与共识里有明显错误（如把 10+2=12 判为 10 以内范围），双标注者 κ≈0.64；(b) 链路 A 的标准特征由构造者自己写，常漏列所需概念（如比例尺、圆柱体积），漏判主要来自这里，链路 B 查全更高但概念过列使查准偏低；(c) 知识点粒度造成的课时边界模糊；(d) 12 册里没有「分数的初步认识/真分数假分数/约分通分」（D11/D14），Stage 5 补全前分数维度的边界只能来自习题里零星出现的用法。

**否决的替代方案**：直接用草稿 `grants` 的自由文本做模糊匹配——不可审计、不可复现；让校验函数调用语言模型判断越界——违反确定性优先，模型只用在"读题 → 特征"与"知识点 → grants"两处，均有 Judgment/缓存。

### D28. 流水线顺序、三值结论、思考模式抽取与验收线

1. **顺序**：Stage 5 定稿 → Stage 6 `enrich`（语义补全按知识点缓存）→ `build` → `apply`（把补全后的 `grants` 写回 `data/knowledge_points.json` 的 `grants` 字段，其余字段原样）→ 再 `build`。整体重跑 Stage 5 的主命令会用抽取草稿覆盖 `grants`，之后须重新执行 `enrich → build → apply`。当前 433 个知识点的 `grants` 均已写回。
2. **三值结论**：`check_item` 返回 `verdict` = `in` / `borderline` / `out`。`borderline` = 所有违例都是"同一单元内稍后才引入"的能力，建议复核（教材自己在单元内前一课时就用后一课时的方法：23 个实例，见 D29；开发集上这类约占链路 B 结论的 14%）。验证闭环的建议用法：`out` → 重写题目；`borderline` → 带着说明交给教师确认；`in` → 放行。
3. **特征抽取用思考模式**（`qwen3.7-plus` thinking，约 0.02 元/题）：开发集上端到端概念漏判明显减少，意图一致子集 decided 口径查全 0.88→0.97，全部标注数据 strict 查全 0.87→0.96；提示词限定概念最多 2 个核心考点。
4. **验收线**：初版"查准查全均 ≥ 0.95"在当前标注数据质量下不可测——双标注者 κ≈0.64，开发集上核对的几条"标注数据 in、校验 out"里至少 3 条是标注数据错（如 `g1a.u1.l02` 的 5+3：加法在下一单元才教；`g2a.u10.l01` 的 45÷6：有余数除法在下学期才教），按课时清单标注者看不出。改为：端到端(B)·意图一致子集·decided 口径查全 ≥ 0.85、查准 ≥ 0.80；标准特征(A)·意图一致子集·decided 查准 ≥ 0.95。理由：越界的代价不对称（超纲题到学生手里是闭环要防的伤害，误报只触发重写/复核），故优先保查全；意图一致子集排除标注噪声最大的条目；decided 口径配合 `borderline` 复核。test 一次性验收：B 意图一致 decided 查准 0.825 / 查全 0.892（n=89，覆盖率 0.86）；A 查准 0.966；非概念维度越界查全（只测边界本身）开发集 0.95 / test 0.89。严格口径、全部标注数据口径同样报告，未达 0.90 的仍如实写出。test 上还观察到 B 的误报主要是抽取器把「比…多几」「单价×数量」这类基础数量关系也列为概念，该问题未在 test 上调参（改提示词须在开发集上做）。

### D29. 「开篇探索」习题先于主知识点引入课时：容忍而不前移引入位置

23 条习题（涉及 11 个知识点）所在课时早于其主知识点的引入课时，且全部在同一单元内——教材有意先让学生探索（如 `g4a.u4.l02`「队列表演（一）」先算 12×15），下一课时才教竖式。这是抽取挂载 / 取最早成员时的口径问题，不是版本对齐遗漏（Stage 5 前移 0 个）。

决策：不修改知识点引入位置，改为在 `tests/test_stage6_invariants.py` 中容忍"同一单元内、仅早于引入课时"的实例（上限 23，防回归），跨单元的一律失败；边界校验对该情形给出 `borderline`（建议复核）。理由：前移引入位置会把"先探索后讲授"的真实教学顺序改写为"先讲授"，并扰动已冻结的 Stage 4/5 产物；占比仅 0.5%，`borderline` 机制已能向下游如实表达不确定性。被容忍的集合是明确枚举、有上限、有教学依据的，不是为过线放宽评测。


### D33. 整数上限的覆盖修复：100 以内取精确值

为了让每条教材习题都不超出所在课时的边界，补全后的覆盖修复会在习题的整数需求超出现有上限时抬高上限。原规则一律抬到位数上限（`10^位数 − 1`）：一年级下册第一单元复习课里一道连加题（7+8=15，再依次加 9、4、8、6、7、5，累计到 50 多）把整数上限抬到了 99，并一直沿用到第四单元之前，导致两位数加减法在 20 以内数的单元里就被判为"在边界内"，超纲检测在低年级早期过宽。

决策：需求不超过 100 时取精确值（该复习课的上限为 24），更大的数仍按位数封顶。效果：低年级早期的整数上限与教材实际一致；生成探针边界通过率 0.999 → 0.998，其余指标不变。残留的不足见 `eval/known_limitations.md`（边界按课时粒度，运算形态标签不区分位数）。

### D34. 分数类型的包含关系：假分数、带分数以真分数为前提

能力边界里的分数类型是五个受控取值：几分之一、几分之几、真分数、假分数、带分数。原先只定义了"真分数 ⊃ 几分之几 ⊃ 几分之一"，而知识库里没有任何知识点授予"真分数"，却有知识点授予"假分数""带分数"（五年级下册），结果学到假分数的课时边界里反而没有真分数，既不符合教学顺序，也会把使用真分数的题误判为超纲。

决策：补充包含关系——假分数、带分数以真分数（及其下位类型）为前提——并在折叠能力边界时按包含关系展开（`FRACTION_IMPLIES`、`Accumulator.merge`），校验与展示共用同一套关系。效果：越界探针端到端查准保持 0.825（只改整数上限时曾降到 0.805），其余指标不变。

### D20. 词法 BM25F + 向量融合 + 年级/领域先验

1. **接口**：`Curriculum`（`chalkbase/query/store.py`）只依赖 `models.py` 的稳定字段，缺失的可选文件（隐含边标记等）容错；隐含边读 `Edge.is_direct == False`。`boundary()` / `check_item()` 转调 `chalkbase.boundary`，未知课时抛 `KeyError`。

4. **年级先验是软先验**：满足需求年级 ×1.2；知识点比需求年级晚 n 年引入乘 0.6ⁿ；最后复现年级早于需求年级乘 0.8ⁿ；领域先验 ×1.3。新版教材把部分内容后移（D10/D14），教师的说法与教材编排可能不一致。

### D27. Stage 5 补全后检索标注数据增量更新；螺旋复习子句加权

## 9. 评测与标注数据方法

评测体系的通则见 [CLAUDE.md](../CLAUDE.md) 第 4 节；这里记录与实现相关的决策。

**独立性原则与模型分工**（D13）：流水线中的语言模型判断（成对判定、题型分组与卡片生成、grants 补全、特征抽取等）用 `qwen3.7-plus`；标注数据首轮盲标用 `qwen3.8-flash` + `deepseek-v4.1-flash`（不同厂商，互不可见，也看不到系统预测），仲裁用 `qwen3.8-max`（思考），仲裁置信度 < 0.7 进入低置信度队列。流水线模型不进入同一任务的标注模型组。每次判断以 `Judgment`（输入摘要、结论、置信度、理由）落盘于 `work/judgments/`。

**可用模型**（人民币元/百万 token，来自阿里云百炼定价页；`deepseek-v4.1-flash` 为同系列 flash 档位的近似值）：

| 模型 | 输入 | 输出 | 用途 |
|---|---|---|---|
| `qwen3.8-max` | 12 | 36 | 仲裁（思考模式）、课标终审 |
| `qwen3.7-plus` | 2 | 8 | 流水线判定与生成 |
| `qwen3.8-flash` | 0.8 | 2.7 | 标注数据首轮盲标 |
| `deepseek-v4.1-flash` | 1 | 2 | 标注数据首轮盲标 |

### D4. 思考模式必须显式指定

`qwen3.8-max`、`qwen3.8-flash`、`qwen3.7-plus`、`deepseek-v4.1-flash` 在**不传** `enable_thinking` 时默认仍产生 `reasoning_tokens`（默认开启思考模式），必须显式传 `enable_thinking: true/false` 才能控制。`chalkbase/annotate/client.py` 的 `AnnotationRequest` 把 `thinking` 设为必填并总是显式传递，避免意外的思考开销。

### D12. 节点与客户端行为

DashScope 有北京（`cn-beijing.maas`）与新加坡（`ap-southeast-1.maas`）两个专属工作空间节点（OpenAI 兼容模式）。两节点实测（4 模型 × 思考/非思考、16 并发 × 48 条成对判定提示词）全部 200、无 429，延迟基本相当（非思考单次中位数 2.0～2.8s；纯网络往返约 0.8～1.1s，其中 TLS 握手约 0.55～0.8s）。

做法：(1) 主节点读 `DASHSCOPE_BASE_URL` + `DASHSCOPE_API_KEY`（北京），可选备用节点 `DASHSCOPE_INTL_BASE_URL` + `DASHSCOPE_INTL_API_KEY`（新加坡），仅在网络错误 / 429 / 5xx 时切换；(2) 每个工作线程持有一个 `requests.Session` 复用 TLS 连接；(3) 缓存键 = (模型, 模式, 提示词哈希)，不含节点——两节点提供同一模型，结果按内容可复现，节点只是传输通道；(4) 只缓存成功的响应，失败（网络错误、欠费 403 等）不入缓存，重跑时重新请求，因此失败结果不会被当作结论。费用统计按国内人民币定价，以北京为主可保证统计不失真。

### D31. DashScope 客户端直连阿里云节点，绕过本机代理

本机配置 HTTP(S) 代理时，高并发批量调用会间歇出现 `ProxyError: Remote end closed connection without response`（节点本身可直连，直连与走代理各 5 次探测均 200）。`chalkbase/annotate/client.py` 导入时把 `.aliyuncs.com` 追加到 `NO_PROXY`，对两个阿里云节点直连，其他域名行为不变。已在运行的进程需重启后生效；重试与缓存保证重跑不重复计费。

### D19. 标注数据抽样复核的范围与局限

对各类标注数据按"一致采纳 / 仲裁采纳"两层分别抽样，共 79 条，由与标注模型组无关的复核者按各任务标注指南盲核（复核时看不到分层、原始标注与标注数据）。结果：75 采纳 / 2 拒绝 / 2 不确定。实体消解成对 24/24、锚点 10/10；前置关系 20/20（1 条不确定）；检索探针 8/8；题型粒度 13/15（2 条拒绝均为"过粗"应为"合适/过细"，原因是标注模型拿模板对比源题，违反指南）。各类准确率的 Wilson 区间见 `reports/eval.md`。

局限：每类 n=8～24，区间下限多数低于 0.95，只能说明"未发现系统性错误"，不能宣称准确率 ≥ 0.95。复核发现两处指南问题并据此修订：(1) 粒度标注数据系统性漏判"过细"，且模型评判模板而非比较源题 → 指南 v2（D26）；(2) 前置/`builds_on` 边界上"用到 ≠ 前置"与"间接依赖算前置"没有优先级 → 指南补 tie-break（"看 B 的核心内容是否依赖 A"）。题型粒度一项复核的是修订前的分组与指南，其结论只用于发现标注漂移，不代表当前粒度标注数据的准确率。

**其他约定**：分层抽样 + val/test 划分（val 开发调参，test 只在阶段验收时跑）；所有比例指标报告 Wilson 置信区间；某阶段的 test 验收未过线并看过其错误样本后，该 test 并入开发集、另抽新验收集（Stage 4 锚点 D15、Stage 7 检索探针 D20），指标定义不变；评测定义的每次调整记入 `eval/CHANGELOG.md`。`python -m chalkbase.eval` 的 pytest 子进程用 UTF-8（见 D18 的沙箱说明）。
