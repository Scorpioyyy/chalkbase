# 标注指南：题型粒度（too_coarse / ok / too_fine）

## 背景

我们把北师大版小学数学 12 本教材的 4000 多道习题，按「主知识点 + 题目形式 + 次知识点 + 操作数特征」归纳成了「题型」。每个题型有一个抽象模板，后续系统会按模板换数、换情境自动出新题。你要判断：**这个题型的划分粒度，是否符合一位小学数学老师心目中的「一种题型」**。

老师眼中的「一种题型」：出题时会说「再来几道这种题」的那个「这种」。同一题型内的题目，**考查同一个知识点、用同一种解法思路、题目结构相同**，只是数字、情境、措辞不同。

## 判断对象与比较方式（v2 新增）

**只比较「源实例」，不评判模板。** 你看到的材料里没有模板（即使有，也不要拿它当依据）。判断只做两种比较：

1. **组内比较（判过粗）**：把本题型的源实例**彼此对比**——它们是不是同一类题？不要拿某个抽象的「理想题型」去量它们，也不要看「一个模板能不能写出来」，只看源实例之间的差别是「参数/情境/措辞」（可接受）还是「考点/问法/解法」（过粗）。
2. **组间比较（判过细）**：把本题型的源实例与「同一主知识点下其他题型」列出的源实例对比——是不是同一类题、被拆开了？

## 三个标签

### `ok`：合适
源实例基本都是同一种题：同一个考点、同一种解题思路、结构一致；数值范围、有无进退位等可以不同（它们是参数，不是题型差别）。

### `too_coarse`：过粗
这个题型里混了**老师会分开讲、分开练**的两种或更多题型，一个模板难以同时生成它们。典型信号：
- 源实例里有的是「计算」、有的是「解释算理/说一说」；
- 同一知识点下，有的是「正向求结果」、有的是「已知结果逆推条件」且解法明显不同；
- 结构差别大（如一部分是单步应用题、一部分是需要列表枚举的复杂问题）；
- 实际上考的是两个不同的考点。

### `too_fine`：过细
这个题型的源实例，与**同一主知识点下列出的其他题型**的源实例其实是同一种题，只是参数（位数、有没有进位、数的大小）或情境不同，老师不会把它们当成两种题型。只有当你能在「同一主知识点下的其他题型」中指出与它本质相同的那个时，才判 `too_fine`，并在 reason 里写出对方编号。**不要因为「只有 1 条实例」就判过细**；也不要因为题型之间的编号相邻、知识点相同就判过细。

`too_fine` 的例子（判过细）：
- 本题型 3 条源实例都是「在方格纸上画出已知图形向右平移若干格后的图形」；同知识点另一题型的源实例也是「画出图形向上平移若干格后的图形」「画出图形向右平移若干格」——同一种画法、同一种考点，只差平移方向和格数 → `too_fine`，指出对方编号。
- 本题型是「笔算 3 位数乘 2 位数」应用题（水果店买苹果），另一题型是「笔算 3 位数乘 2 位数」应用题（图书馆买书），只是情境不同、结构一致 → `too_fine`。

不是 `too_fine` 的例子（判 ok 或 too_coarse）：
- 一个是「计算 0.8＋0.35」，另一个是「0.8 米加 0.35 米一共多少米」——一个纯计算、一个应用题，老师会分开练 → 不是过细。
- 一个是「由图读出数据」，另一个是「根据数据补全统计图」——问法和作答方式不同 → 不是过细。
- 一个是「已知两数求和」，另一个是「已知和与一个加数求另一个加数」——正向与逆向，解法不同 → 不是过细。

## 判定要点

1. 只有 1 条源实例的题型：只看是否「过细」（能否与同知识点的其他题型合并），不会「过粗」。
2. 题目形式（填空/判断/选择/计算/应用题/画图……）不同通常就是不同题型，不要仅因为同一知识点下既有填空又有判断就判 `too_fine`。
3. 无编号的批量题（一组口算、一排判断）在教材中整体记作 1 条源实例，这很正常。
4. 模板写得好不好不是本任务的判断对象，只看源实例之间（及与其他题型源实例之间）的异同。
5. 单条实例内含多个小问时，按其主要考查点判断；小问里夹带的次要问法（如计算题后面顺带「说一说你是怎么想的」）不算混杂。
6. 差别只在数的大小、位数、有无进退位、情境、人名物名、措辞，不算混杂（这些是参数）；差别在「考什么 / 怎么答（算、画、说理、判断、选择）/ 解法思路（正向求值或逆向求条件）」才算混杂。
7. 拿不准时：源实例看起来都是「再来几道这种题」时的同一种题，就判 `ok`，不要为了显得严格而判过粗。

## 另外请给出

`verifiable_type`：这个题型的答案能否被程序唯一算出——`program`（计算、填数、判断对错、选择、数值应用题等）/ `rule`（可以按规则检查但答案不唯一，如画图、分类方案）/ `human`（开放表达：说一说理由、谈感受、调查报告）。

## 输出格式

只输出 JSON：

```json
{"label": "too_coarse" | "ok" | "too_fine", "verifiable_type": "program" | "rule" | "human", "confidence": 0.0~1.0, "reason": "不超过60字"}
```
