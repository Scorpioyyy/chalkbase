# Stage 3 评测规格：题型归纳、情境库、表述规范

细化自 `eval/specs/overview.md`，按 CLAUDE.md 4.1 节流程。

**输入**：Stage 2 冻结产物（`data/knowledge_points.json`、`data/kp_local_map.json`、`data/lessons.json`）+ Stage 1 观测（`work/books/*/exercises.json`、`contexts_observed.json`、`glossary_observed.json`）。
**输出**：`data/exercises.json`（4319 条实例，知识点引用改写为规范 ID）、`data/archetypes.json`（`ItemArchetype`）、`data/contexts.json`（`Context`）、`data/glossary.json`（`GlossaryEntry`）、`work/judgments/stage3_*.jsonl`。

## 1. 失败模式清单

1. **实例未归属 / 引用悬空**：某实例不属于任何题型；题型引用的实例、知识点、情境不存在。
2. **粒度过粗**：老师眼中不同的题型被合并为一个模板（如「小数加法（不进位）」与「小数减法（退位）」共用一个模板，或同一知识点的计算题与应用题混在一起）。
3. **粒度过细**：同一题型被拆成多个长尾模板。
4. **参数约束脱离教材观测**：约束过宽（生成出超出教材范围的题）或过窄（千篇一律）；槽位约束与该组实例观测包络矛盾。
5. **模板/求解程序写错**：`program` 类模板在约束内采样时求解程序报错、返回浮点、违反自身约束，或改写示例答案与程序重算不一致。
6. **改写示例复述教材原题**：违反 CLAUDE.md 第 3 节。
7. **可验证类型标错**：开放表达题被标成 `program`，或可程序求解的计算题被标成 `human`。
8. **难度不合理**：难度与可解释特征不单调、各年级难度分布塌缩到一两个等级。
9. **情境库归并错误**：不同情境被合并 / 同一情境被拆分；数值范围不是观测包络。
10. **表述规范汇总遗漏**：各书观测到的术语、措辞在汇总后丢失。

## 2. 检测手段

| 失败模式 | 检测手段 |
|---|---|
| 1 | 不变量（pytest）：每个实例恰好属于一个题型；`source_instance_ids`、知识点、`allowed_contexts` 全部可解析 |
| 2、3 | **粒度标注数据**：模型组对抽样题型三分类（过粗 / 合适 / 过细），抽样复核；单实例题型占比与过细率（见 §4） |
| 4 | 不变量：每个 `program` 题型的槽位约束落在该组实例观测包络内（整数位数、小数位数不超过观测最大值）；生成探针 |
| 5 | **生成探针**：每个 `program` 题型在槽位约束内随机采样 20 组参数，求解程序必须 100% 可运行、返回非浮点、满足约束表达式，且约束接受率 ≥ 1%（D18）；每个改写示例答案必须等于程序重算结果（不变量，100%） |
| 6 | 不变量：改写示例与该题型全部源实例 `text` 的字符 5-gram 重合率 < 0.5（超过即判复述） |
| 7 | 粒度标注数据同时让模型组给出可验证类型判断，报告一致率（信息性，不设阈值）；`program` 类必须有求解程序（不变量） |
| 8 | 不变量：难度特征原值保存；每个年级内难度 1～5 各等级都非空（年级内题型数 ≥ 10 时）；报告难度与特征的 Spearman 相关 |
| 9 | 不变量：每个实例的非空情境主题都映射到情境库条目；抽查原始主题→情境映射（情境仅作生成参考，归并错误影响有限） |
| 10 | 不变量：各书 `glossary_observed.json` 中每个 term 都出现在 `data/glossary.json` 的 term 或 aliases 中 |

## 3. 分组方法（D26）

**分组 = (主知识点规范 ID, 题目形式 `item_form`) 内的语义细分**：

1. 先按 (主知识点, 题目形式) 分组（1179 组，其中 374 组只有 1 个实例）；
2. 对每个含 ≥ 2 个实例的组，用流水线模型 `qwen3.7-plus`（非思考，D13；不进入粒度标注组）读全部实例原文与答案形式，按「考什么、怎么答、解法思路」划分子组，每个子组一个题型（`chalkbase/stage3/partition.py`；每次判断以 Judgment 落盘到 `work/judgments/stage3_partition.jsonl`）。拆分的依据：作答方式大类（计算求值 / 画图操作 / 判断选择 / 读图读表 / 开放表达）不同、正向求值与逆向求条件、一步直接算与多步综合、考点不同；**不拆**数的大小、位数、有无进退位、情境、措辞、次要知识点。"宁合勿拆"；
3. 操作数分桶、次知识点集合不作为分组依据（它们仍进入参数观测包络与卡片的槽位约束）。无回退、无挂靠：单实例子组就是单实例题型；
4. 实例集合与上一版某题型完全相同的，直接复用已通过校验的卡片，只为新产生的题型生成卡片（D18 校验与修复流程不变）。

**对照方案 v1**：签名 =（主知识点, 形式, 次知识点集合, 操作数粗分桶），单实例组逐级回退到更粗层级并挂靠到最近的题型（`chalkbase/stage3/grouping.py:group_instances`）。失败原因：粒度标注数据上 66% 以上为"过粗"——数字特征分不出作答方式与问法，回退把不同类的单实例并进来（D26）。

操作数粗分桶（v1 签名与基线 B 使用）：数的类型集合 / 整数位数 ≤1·2·3·4·5–8·≥9 / 小数位数 0·1·2·≥3 / 进位退位 / 整除 / 运算步数 ≤1·2·≥3。无编号批量题合并成 1 条实例（D7），其 `operand_features` 是整组的典型特征。

## 4. 指标、阈值与动作

| 指标 | 定义 | 阈值 | 不达标动作 |
|---|---|---|---|
| 粒度"合适"占比 | 粒度标注数据上 label=合适 的比例（Wilson CI；指南 v2） | ≥ 0.80（由先验的 0.85 调整，指标定义不变，见 `eval/CHANGELOG.md` 与 D26）；一轮改进后 ≥ 0.70 且边际收益下降即停 | 过粗多 → 细分更积极；过细多 → 合并更积极 |
| 生成探针程序可验证率 | `program` 题型 × 20 次采样中求解成功且满足约束的比例 | = 1.0 | 修模板或约束，无容忍度 |
| 改写示例程序重算一致率 | `program` 类示例答案与程序重算一致 | = 1.0（不变量） | 重新生成该题型 |
| 单实例题型过细率（门槛） | 粒度标注数据中 n_instances=1 的题型被判 too_fine 的比例（Wilson CI） | ≤ 0.10（D26） | 过细多 → 单实例并入同组最相近题型 |
| 单实例题型占比 | 只含 1 个实例的题型数 / 题型总数 | 仅报告（数据下限 18.6% 已使原阈值 0.15 不可达） | — |
| 单实例题型超额占比 | （单实例题型数 − 数据下限个数）/ 题型总数；数据下限 = 按 (主知识点, 形式) 分组时只有 1 个实例的组数 | 仅报告（D26） | — |
| 压缩率 | 实例数 / 题型数 | ≥ 2.0（基线 B 的 2.045 之下视为过碎） | 细分过碎 → 收紧 |
| 可验证类型分布 | program / rule / human 数量 | 报告 | — |

单实例题型有两种来源：教材数据稀疏（某知识点的某种题目形式在教材里只出现一次，4319 条实例分散在数百个知识点 × 9 种题目形式上），与分组过细。"超出数据下限"的口径用于区分二者；过细率直接度量后者。

## 5. 评测数据

- **粒度标注数据**（指南 v2）：从全部题型中分层抽样 150 个（按年级段 × 领域 × 题型规模〔1 个实例 / 2–4 / ≥5〕分层），val/test 各 75。标注者看到题型的主知识点、题目形式、全部源实例的 `text`（最多 8 条，前 160 字）以及**同一主知识点下其他题型的源实例摘要**（用于判断过细）；不看模板（指南 v2：只比较源实例，不评判模板）。流程同 CLAUDE.md 4.3：首轮 `qwen3.8-flash` + `deepseek-v4.1-flash`，仲裁 `qwen3.8-max` 思考模式。
- **开发迭代只用 val**：改动分组方案时，用 `python -m chalkbase.stage3.gold dev` 在建卡片之前对分组抽样、只标 val 一半（`eval/annotation/archetype_granularity_dev/<标签>/`），test 不参与调参；最终方案建好卡片后再按完整流程出 val/test 标注数据。
- **对照方案重标**：用 v2 指南重标 v1 方案的同一批 150 个题型（`archetype_granularity_oldscheme`），以及基线 B 的 40 个分组（`archetype_granularity_baseline`）。旧指南下的数字不再与 v2 方案直接比较。
- **抽样复核**：一致采纳、仲裁采纳各抽样（见 `reports/eval.md`）；复核的是修订前的分组与指南，结论用于发现标注漂移（D19）。
- **生成探针**：对全部 `program` 题型跑（确定性，不抽样）。

## 6. 基线

- 对照组 A「每个实例单独成题型」：压缩率 1.0，单实例占比 1.0。
- 基线 B「签名完全相同才归为一组（无回退）」：2112 个题型，压缩率 2.05，单实例占比 59.9%；对其 40 个分组做粒度打分。
- 方案 v1「签名分桶 + 回退挂靠」：用指南 v2 重标同一批样本，作为分组改进的前后对照。

## 7. 最终结果与误差分析

粒度标注数据均为指南 v2，"合适"比例带 Wilson 95% CI。

| 方案 | 题型数 | 压缩率 | 单实例（占比 / 超出下限） | val 合适 | test 合适 | 过粗 / 过细（val+test） |
|---|---|---|---|---|---|---|
| v1 签名分桶 + 回退 | 1507 | 2.87 | 374（24.8%）/ 0 | 0.595 [0.481, 0.699]（44/74） | 0.613 [0.500, 0.715]（46/75） | 53 / 6 |
| 基线 B 签名完全相同 | 2112 | 2.05 | 1266（59.9%）/ 0.42 | 0.737（14/19，n=40 抽样） | 0.650（13/20） | 11 / 1 |
| **v2 (主知识点, 形式) 内语义细分** | 2009 教材题型（另有 59 个无教材实例的 reconciled 题型） | 2.15（教材题型） | 1042（51.9%）/ 0.332 | **0.892 [0.801, 0.944]**（66/74） | **0.863 [0.766, 0.924]**（63/73） | 15 / 3 |

- **验收（test）**：粒度合适 0.863 ≥ 0.80 通过；单实例题型过细率 0.025 [0.004, 0.129]（n=40）≤ 0.10 通过；压缩率 2.15 ≥ 2.0 通过；生成探针 `program` 可验证率 1.0（1313 个题型 × 20 次 = 26260 次采样），示例重算一致率 1.0（不变量）。单实例占比 0.519 与超出下限 0.332 如实报告，不作门槛。
- **可验证类型**：`program` 1313 / `rule` 367 / `human` 388（含缺口与补全题型）；程序校验 6 轮修复后仍未通过、如实降级为 `human` 的教材题型 5 个。
- **v1 的失败**：val 上 26 个"过粗"几乎全是同一 (主知识点, 形式) 组里作答方式不同（计算 / 说理 / 画图 / 连线 / 开放探究），少数为正逆混杂、应用题数量关系模型不同；回退合并不是主因，主因是数字特征分不出作答方式（D26）。
- **v2 的剩余误差**：过粗（val 6 / test 9）集中在形式为 `other` 的开放探究类与 `word_problem` 中多种数量关系并存的组；过细 3 例。v2 的单实例题型占比偏高（超出下限 0.332）是"同组内明显不同类"的单实例子组，被判过细的仅 2.5%，所以是更细致的分类而非长尾碎片；对教师展示时，仍建议把同知识点的相近题型合并呈现。
- **标注数据质量**：首轮 κ = 0.44（v2 分组，150 条；一致 125 / 仲裁 22 / 失败 3，失败为仲裁模型网络错误，不计入分母），旧方案重标 κ = 0.73。v2 分组 κ 低是类别分布极不均衡所致（绝大多数为 ok），原始一致率 0.83。
- **缺口与补全题型（reconciled）**：Stage 5 补建的 14 个缺口知识点按"知识点 × 建议方向"生成 49 个题型（`chalkbase/stage3/gaps.py`），无教材源实例，参数包络按引入年级取保守上限；`program` 39 / `rule` 9 / `human` 1，D18 校验全部适用，0 个降级。另有 10 个无主习题的可考查知识点各补 1 个题型（D32）。粒度标注数据不覆盖这两类（无源实例可比较）。
- 标注数据 `archetype_id` 与最终题型 ID 已逐条核对一致（150/150，实例数相同）。
