# Stage 3 评测规格：题型归纳、情境库、表述规范

细化自 `eval/specs/overview.md` 的 Stage 3 一节，按 CLAUDE.md 4.1 节流程执行。

**输入**：Stage 2 冻结产物（`data/knowledge_points.json`、`data/kp_local_map.json`、`data/lessons.json`）+ Stage 1 观测（`work/books/*/exercises.json`、`contexts_observed.json`、`glossary_observed.json`）。
**输出**：`data/exercises.json`（4319 条实例，知识点引用改写为规范 ID）、`data/archetypes.json`（`ItemArchetype`）、`data/contexts.json`（`Context`）、`data/glossary.json`（`GlossaryEntry`）、`data/judgments/stage3_*.jsonl`。

## 1. 失败模式清单

1. **实例未归属 / 引用悬空**：某实例不属于任何题型；题型引用的实例、知识点、情境不存在。
2. **粒度过粗**：老师眼中不同的题型被合并为一个模板（如「小数加法（不进位）」与「小数减法（退位）」共用一个模板，或同一知识点的计算题与应用题混在一起）。
3. **粒度过细**：同一题型被签名分桶拆成多个长尾模板（只差一个操作数位数的桶）。
4. **参数约束脱离教材观测**：约束过宽（生成出超出教材范围的题）或过窄（千篇一律）；槽位约束与该组实例观测包络矛盾。
5. **模板/求解程序写错**：`program` 类模板在约束内采样时求解程序报错、返回浮点、违反自身约束，或改写示例答案与程序重算不一致。
6. **改写示例复述教材原题**：违反 CLAUDE.md 第 3 节。
7. **可验证类型标错**：开放表达题被标成 `program`，或可程序求解的计算题被标成 `human`。
8. **难度不合理**：难度与可解释特征不单调、各年级难度分布塌缩到一两个等级。
9. **情境库归并错误**：不同情境被合并 / 同一情境被拆分；数值范围不是观测包络。
10. **表述规范汇总遗漏**：各书观测到的术语、措辞在汇总后丢失。

## 2. 检测手段

| 失败模式 | 检测手段 |
|---|---|
| 1 | 不变量（pytest）：每个实例恰好属于一个题型；`source_instance_ids`、知识点、`allowed_contexts` 全部可解析 |
| 2、3 | **粒度金标**：模型组对抽样题型三分类（过粗 / 合适 / 过细），人工抽样核验；单实例题型占比（见 §4 两个口径） |
| 4 | 不变量：每个 `program` 题型的槽位约束落在该组实例观测包络内（整数位数、小数位数不超过观测最大值）；生成探针 |
| 5 | **生成探针**：每个 `program` 题型在槽位约束内随机采样 20 组参数，求解程序必须 100% 可运行、返回非浮点、满足约束表达式；每个改写示例答案必须等于程序重算结果（不变量，100%） |
| 6 | 不变量：改写示例与该题型全部源实例 `text` 的字符 5-gram 重合率 < 0.5（超过即判复述） |
| 7 | 粒度金标同时让模型组给出可验证类型判断，报告一致率（信息性，不设阈值）；`program` 类必须有求解程序（不变量） |
| 8 | 不变量：难度特征原值保存；每个年级内难度 1～5 各等级都非空（年级内题型数 ≥ 10 时）；报告难度与特征的 Spearman 相关 |
| 9 | 不变量：每个实例的非空情境主题都映射到情境库条目；Agent 抽查 30 条原始主题→情境映射并记录正确率（本阶段不做人工核验，理由：情境仅作生成参考，归并错误影响有限，最终停顿点再抽查） |
| 10 | 不变量：各书 `glossary_observed.json` 中每个 term 都出现在 `data/glossary.json` 的 term 或 aliases 中 |

## 3. 签名与粗分桶规则（KICKOFF Stage 3 第 2 步）

签名 = （主知识点规范 ID，题目形式 `item_form`，次知识点规范 ID 集合，操作数粗分桶）。操作数粗分桶：

| 维度 | 分桶 |
|---|---|
| 数的类型 | `number_types` 集合原样（整数/小数/分数/百分数…的组合） |
| 整数位数 | ≤1 / 2 / 3 / 4 / 5–8 / ≥9 |
| 小数位数 | 0（或空）/ 1 / 2 / ≥3 |
| 进位退位 | 是 / 否 / 未涉及 |
| 整除 | 是 / 否 / 未涉及 |
| 运算步数 | ≤1 / 2 / ≥3 |

注意 D7：无编号批量题合并成 1 条实例，其 `operand_features` 是整组的典型特征。

**签名回退**（针对失败模式 3）：若某完整签名组只有 1 个实例，依次回退到更粗的签名层级——(主知识点, 形式, 次知识点集合) → (主知识点, 形式)——与同层级的其他实例合并；回退只在同一主知识点、同一题目形式内进行，不跨知识点、不跨形式合并。回退后仍只有 1 个实例、但同一（主知识点, 形式）下已有多实例题型的，并入签名最接近的那个题型（接近度 = 次知识点集合是否相同 + 操作数分桶相同的维度数）；同一（主知识点, 形式）下再无其他实例的，保留为单实例题型（数据本身稀疏）。按此设计，原口径单实例占比的理论值等于数据下限，诊断口径主要用于监控实现是否偏离设计；粒度是否合适由粒度金标判定（挂靠可能导致过粗，由粒度打分暴露）。

## 4. 指标、阈值与动作

| 指标 | 定义 | 阈值 | 不达标动作 |
|---|---|---|---|
| 粒度「合适」占比 | 粒度金标上 label=合适 的比例（Wilson CI） | ≥ 0.85 | 过粗多 → 细化分桶；过细多 → 加强回退 |
| 生成探针程序可验证率 | `program` 题型 × 20 次采样中求解成功且满足约束的比例 | = 1.0 | 修模板或约束，无容忍度 |
| 改写示例程序重算一致率 | `program` 类示例答案与程序重算一致 | = 1.0（不变量） | 重新生成该题型 |
| 单实例题型占比（原口径） | 只含 1 个实例的题型数 / 题型总数 | ≤ 0.15（overview 原阈值，保留不改） | 检查分桶 / 回退 |
| 单实例题型超额占比（诊断口径，新增） | （单实例题型数 − 数据下限个数）/ 题型总数；数据下限个数 = 按 (主知识点, 形式) 分组时只有 1 个实例的组数（任何不跨知识点/形式合并的方法都必然保留这些单实例题型） | ≤ 0.05 | 分桶引入的长尾过多 → 调粗分桶 |
| 压缩率 | 实例数 / 题型数（相对「每实例一个题型」对照组） | 报告 | — |
| 可验证类型分布 | program / rule / human 数量 | 报告 | — |

新增诊断口径的理由见 `eval/CHANGELOG.md`：Stage 0 定阈值时尚无数据；Stage 1 数据显示 4319 条实例分散在数百个知识点 × 9 种题目形式上，大量知识点在教材里某种形式只出现一次，这类单实例题型源于教材数据稀疏，不是「粒度过细」。原口径照常报告、照常按原阈值判定是否达标，诊断口径用于区分两种来源、指导改进方向。

## 5. 评测数据

- **粒度金标**：从全部题型中分层抽样 150 个（按年级段 × 领域 × 题型规模〔1 个实例 / 2–4 / ≥5〕分层），val/test 各 75。标注者看到题型的模板、签名、全部源实例的 `text`（最多 8 条）以及**同一主知识点下的其他题型列表**（用于判断过细），输出 过粗/合适/过细 + 可验证类型。流程同 CLAUDE.md 4.3：首轮 `qwen3.8-flash` + `deepseek-v4.1-flash`，仲裁 `qwen3.8-max` 思考模式；流水线模板生成模型 `qwen3.7-plus` 不进入标注组。
- **人工核验**：一致采纳、仲裁采纳各抽 8 个，连同人工队列（上限 6）。
- **生成探针**：对全部 `program` 题型跑（确定性，不抽样）。

## 6. 基线

- 对照组 A「每个实例单独成题型」：压缩率 1.0，单实例占比 1.0。
- 基线 B「签名完全相同才归为一组（无回退）」：报告题型数、单实例占比，并对其抽样做粒度打分（与正式方法同一批标注者、同样本量 40），比较「合适」占比。
