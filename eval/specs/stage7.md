# Stage 7：查询接口评测规格

本文件把 `overview.md` 的 Stage 7 部分细化。接口见 `chalkbase/README.md`；检索探针金标见 `eval/gold/{val,test}/retrieval_probe.jsonl`（60 条，val/test 各 30，核心/相关两档）。

## 1. 失败模式与检测手段

| # | 失败模式 | 检测手段 |
|---|---|---|
| F1 | 别名/说法缺失：教师口语（"竖式"、"分蛋糕"、"几个几相加"）与知识点名称/描述用词不同，检索不到 | 检索探针 recall@5 / MRR；错误分析按"首个核心命中的名次"与失败原因归类 |
| F2 | 通用词干扰：「出几道题」「最好」「情境」等需求套话匹配到无关知识点 | 同上；基线与改进版逐条对比，失败样本人工归类 |
| F3 | 年级/单元定位不符：教师说的年级与教材实际编排不一致（D14：三年级面积），或同一内容在多个年级出现而返回了错误年级 | 探针中的年级一致率（返回的前 5 个核心命中里年级在需求年级及以前的比例，诊断指标，不设阈值）；p08/p35/p47 单独列出 |
| F4 | 跨单元/总复习类需求只命中一小块（核心集合很大，top-5 全落在一个主题） | 探针 type=cross_unit/spiral 的分层指标；诊断：top-10 覆盖的主线数 |
| F5 | 螺旋复习类需求只返回当前知识点，漏掉「之前学的」那部分（related 档） | 诊断指标：核心+相关 recall@10（不设阈值，related 档金标由模型仲裁，噪声较大） |
| F6 | 接口行为错误：前置链漏边/多边、深度不对、方向反了；「某课时之前已学」不单调；引用不可解析；过滤条件失效 | `tests/test_query.py`：不依赖具体知识点数量的小断言（单调性、方向互逆、过滤结果满足条件、返回的 ID 都能解析、depth=1 ⊆ depth=2） |
| F7 | 数据变更后接口失效（Stage 5 增删知识点、边增加 `is_direct=False`；Stage 3 重写题型） | 接口只依赖 `models.py` 中稳定字段；缺失文件/字段容错；测试不写死数量；金标中已不存在的 ID 在评测中单独计数并跳过 |
| F8 | 非确定性：同一查询两次结果不同 / 向量缓存缺失导致离线不可用 | 测试：同一查询重复调用结果一致；向量检索缺缓存时自动降级为词法检索（并给出警告） |
| F9 | 能力边界接口与 Stage 6 脱节 | `boundary()` / `check_item()` 转调 `chalkbase.boundary`；测试检查返回类型、单调性、未知课时报 `KeyError`，不依赖数值 |

暂不检测：教师真实口语的分布偏移（探针由人起草的 60 条，措辞比真实输入书面，已在 `retrieval_probes.md` 说明）；检索延迟（知识点总数 ~400，毫秒级，不构成风险）。

## 2. 指标定义

对每条探针，检索返回按分数降序的知识点列表 `R`；金标 `core`（必须命中）、`related`（诊断用）。核心集合大小差异很大（1～37，跨单元类需求为 9～37），所以原始 recall@5 的上限是 5/|core|，无法在大集合上达到阈值。因此采用**封顶 recall**：

- `recall@k = |R[:k] ∩ core| / min(|core|, k)`（k=5 为主指标，另报 k=10）。|core|≤k 时即普通 recall；|core|>k 时表示"前 k 个全是核心"为满分。
- `hit@5 = 1[R[:5] ∩ core ≠ ∅]`（比例型，报 Wilson 95% CI）。
- `MRR = 1 / (首个核心命中的名次)`，top-50 内无命中记 0。
- `recall@5`、`MRR` 是逐条取值于 [0,1] 的均值而非二项比例，其 95% CI 用 bootstrap（10000 次，固定种子）报告；hit@5 用 Wilson。
- 诊断：`recall@10`、核心+相关 `recall@10`（同样封顶，分母 `min(|core ∪ related|, 10)`）、年级一致率、按 `type` 分层的 recall@5/MRR。
- core 为空的探针（1 条，需求无对应知识点）不参与指标，单独计数。
- p08、p35、p47（D14：长方形/正方形面积缺口，Stage 5 补全后金标要更新）：主指标含这 3 条；另报"排除 D14 三条"的数值与这三条各自的名次。

数据划分：val 用于开发与调参（词表、权重、融合方式），test 只在验收时跑一次。样本量 n=30 每划分，hit@5 的 Wilson 半宽约 0.07～0.10，对 recall/MRR 同量级——这是金标规模（overview 的"60 条即评测数据本身"）决定的，不再扩充；改进结论以 val+test 合并 60 条的方向一致性为准，不在 test 上调参。

## 3. 阈值与动作

- recall@5 ≥ 0.85，MRR ≥ 0.70（沿用 overview；recall@5 采用上面的封顶定义，理由：核心集合 >5 时原始 recall 不可能达标，是指标定义问题而不是检索问题，记入 `eval/CHANGELOG.md`）。
- 不变量（`tests/test_query.py`）100% 通过。
- 动作：不达标则先看基线差距；方法本身不够时，依次尝试 ①需求预处理（年级/学期/领域解析、套话剔除）②BM25 与字段加权、③同义词/口语说法扩展、④年级先验、⑤向量检索（DashScope embedding，缓存于 `.cache/`）与词法融合。每项改进单独记录相对基线与上一版的变化。

## 4. 基线

对每个知识点的 `名称 + 别名 + 描述` 拼成文本，字符 1～2 gram 的 TF-IDF，余弦相似度，不做任何需求预处理。基线结果与每次改进的变化见 `reports/eval.md` 的 Stage 7 一节与本文件末尾的"改进记录"。

## 5. 改进记录

### 5.1 验收集更换（评测演进）

首次验收（原 test 30 条，n=29 有效）：基线 recall@5 0.602 / MRR 0.672，改进版 recall@5 **0.761**（未达 0.85）/ MRR 0.811。此时已看过原 test 的错误样本，不能再把它当作未见过的验收集：按 Stage 4 先例（D15 补充）把原 test 并入开发集，另写 30 条全新探针（`eval/probes/retrieval_probes_holdout.md`，h01–h30，编写时不参照系统输出），用同一指南、同一模型组生成金标（`chalkbase/query/holdout_gold.py`，费用 4.53 元；3 条金标 core 为空——教材无对应内容，不计入指标）。此后 `--split val` = 开发集 60 条（有效 59），`--split test` = 新验收集（有效 27）。首次验收之后没有再针对新验收集调整任何参数。

### 5.2 开发集改进梯度（`--split val`，n=59，recall@5 为封顶口径）

| 步骤 | recall@5 | MRR | hit@5 | recall@10 |
|---|---|---|---|---|
| 基线：TF-IDF 字符 1–2 gram（名称+别名+描述） | 0.640 | 0.667 | 0.864 | 0.757 |
| A. BM25F 字符二元组（名称/别名/主线/描述/引入课时标题加权，k1=1.4 b=0.6） | 0.703 | 0.716 | 0.864 | 0.799 |
| B. + 需求解析与套话剔除（年级/学期/领域/范围词/「出几道」等） | 0.703 | 0.732 | 0.881 | 0.798 |
| C. + 年级/领域先验（多年级取最大；晚于需求年级 ×0.6ⁿ，早于 ×0.8ⁿ；领域 ×1.3） | 0.779 | 0.800 | 0.915 | 0.867 |
| D. + 综合/总复习类需求（仅范围词时按年级/领域取可考查知识点，按主线分散） | 0.810 | 0.839 | 0.949 | 0.886 |
| E. + DashScope text-embedding-v4 向量与词法线性融合（权重 0.5） | **0.833** | **0.879** | 0.966 | 0.904 |

各步的参数（融合权重 0.35–0.65、年级惩罚系数、字段权重）在开发集上都落在平台区，没有挑尖峰值。试过但**没有采用**：字符三元组（MRR 下降）、单字 unigram（持平）、多主题拆分 + RRF（"A和B"拆成子查询，top-5 无变化，不符合"无失败指标对应就不加组件"）、仅在最先子句降权后续子句（低于等权）。

### 5.4 主要失败类别（错误分析）

1. **螺旋复习类（占失败最大）**：需求同时提到"当前在学 A"和"复习以前的 B"，核心答案是 A，但 B 的词面更丰富（如「学小数除法时把小数乘法和除法竖式都带上」→ 返回小数乘法）。需要区分"当前主题"与"复习内容"的意图解析（Stage 7 之外或后续迭代：识别"正在学/学…的时候/…之前"等句式），暂未做。
2. **多知识点覆盖**：核心集合大（≥5）时 top-5 只覆盖其中一部分（如「解方程」「长方体展开图」同主题的多个知识点）；封顶 recall 已经只要求 top-5 全是核心，剩余损失来自把相邻但非核心的知识点排在前面。
3. **总复习/综合卷**：范围词需求缺少文本信号，靠年级/领域先验与主线分散，结果可用但与金标的"代表性主干"不完全一致（h24、h30）。
4. **D14 缺口**（p08/p35/p47）：长方形面积等知识点在库里不存在，Stage 5 补全后需更新金标并复测，当前这三条的名次见 `reports/eval.md`。
5. **金标噪声**：两模型标注者在并集上 Cohen κ 仅 0.26（原 60 条）/ 0.11（新 30 条），core/related 边界有较大随意性；这会拉低任何系统的 recall，也说明指标应读作"相对基线的改善"而不是绝对值。
