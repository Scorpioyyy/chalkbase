# 总体评测方案

本文件是起点，不是终稿。每个 Stage 正式实现前，按 CLAUDE.md 4.1 节的流程在本目录下细化出 `eval/specs/stageN.md`，届时可以调整本文件里的具体数字（样本量、阈值），但不应改变已发现失败模式的检测覆盖。

三层评测（不变量 / 组件指标 / 下游探针）的定义见 CLAUDE.md 4.2 节。样本量估算方法：对比例型指标（P/R/F1、通过率），目标 Wilson 95% CI 半宽 ≤ 0.05 时，真值在 0.5 附近约需 n≈380；真值接近 0.9 附近约需 n≈140。下面各阶段的样本量按"金标构造成本低（模型标注）"和"人工只做抽样核验"两种情形分别给出。

## Stage 1：抽取观测

**失败模式**
1. 漏抽：页面上有习题但未生成 `ExerciseInstance`。
2. 误抽：生成了教材上不存在的习题（幻觉）。
3. 知识点粒度错误：把一个考点拆成多个，或把两个不同考点合并成一个。
4. 关键字段错误：`item_form` / `answer_form` / `operand_features` / `primary_knowledge_point_id` 标错。
5. 课时归属错误：习题被记到错误的课时。
6. `text` 摘录失真：原文摘录与图片描述丢失关键信息（如漏掉图中的数值）。
7. 版本信息读错：封面/版权页的审定年份、课标版本记错。

**检测手段**
- 不变量（1,2,5 部分）：Schema 合法；每课时至少一个知识点；页面练习标记 vs 实例数一致性检查（用页面上"练一练/巩固练习"等版式标记做启发式计数，与该页生成的实例数比对，偏差过大触发人工复核清单）。
- 双盲一致性（3,4,6 部分）：每本书抽 2 个单元，两个互不知情子 agent 独立抽取，计算知识点集合 Jaccard、实例字段级一致率（逐字段计算一致比例）。
- 人工核对（1,2,4,6,7）：试点阶段核对约 5 页，之后每批完成后再抽 3～5 页复核，计算实例查全/查准与关键字段准确率。

**评测数据**：无需外部模型金标（本阶段的"金标"就是双盲结果 + 人工核对），人工核对样本 5～10 页/批，覆盖有文字层/无文字层各至少一批。

**阈值与动作**：实例查全率 ≥ 0.95、查准率 ≥ 0.95、关键字段准确率 ≥ 0.90；任一低于阈值 → 修订《抽取指南》，重跑该书。双盲知识点集合 Jaccard ≥ 0.8 才认为指南无歧义可推广到其余书。

**基线**：无（本阶段本身即观测抽取，无更简单的对照方法）。

## Stage 2：知识点实体消解

**失败模式**：应合并未合并（漏并）、不该合并却合并（误并，最危险——会抹掉螺旋扩展）、把螺旋扩展（如"万以内数"vs"亿以内数"）误判为同一、blocking 阶段漏掉真正应比较的候选对。

**检测手段**：blocking 召回率（金标应合并对有多少进入候选）；成对判定 P/R/F1（对 `same`/`extends`/`different` 三分类分别报告，重点看 `different`→`same` 的误判率）；聚类结果 B-cubed precision/recall；"扩展被误判为同一"比例单独报告（这是本阶段风险最高的失败模式，即使整体 F1 达标也要单独过线）。

**评测数据**：按 CLAUDE.md 4.3 节流程生成金标——从全部候选对中分层抽样（按相似度分档：高/中/低相似度各若干），目标每档 ≥ 60 对，共约 200～300 对首轮标注；分歧仲裁后人工核验约 40～60 对（一致采纳、仲裁采纳各抽一半）。

**阈值与动作**：blocking 召回率 ≥ 0.95（不达标则引入 bge-small-zh 向量召回，见 KICKOFF 187-188 行）；成对判定 F1 ≥ 0.85；扩展误判为同一的比例 ≤ 0.05；聚类 B-cubed F1 ≥ 0.85。不达标 → 回到候选生成规则或判定 prompt。

**基线**：名称完全匹配合并。

## Stage 3：题型归纳

**失败模式**：粒度过粗（老师眼中不同的题型被合并为一个模板）、粒度过细（同一题型被拆成多个长尾模板）、参数约束脱离教材观测（约束过宽导致生成越界题，或过窄导致生成千篇一律）、`program` 类改写示例算错、情境库归并错误（不同情境被合并/同一情境被拆分）。

**检测手段**：粒度由模型组三分类打分（过粗/合适/过细）+ 人工抽样核验；生成探针——每个模板在约束内随机采样生成题，程序可验证率（`program` 类必须 100% 可由程序求解且与预期答案一致）；单实例题型（长尾）占比作为粒度过细的信号；不变量——每个实例归属某题型、每个题型引用的情境在情境库中。

**评测数据**：粒度打分抽样约 150 个题型（覆盖各年级各领域）交模型组评分，人工核验其中约 40 个；生成探针对**全部**题型跑（确定性检查，不是抽样）。

**阈值与动作**：粒度"合适"占比 ≥ 0.85；`program` 类生成探针可验证率 = 1.0（任何不通过都必须修模板或约束，不设容忍度）；单实例题型占比 ≤ 0.15（超过则检查签名分桶是否过细）。

**基线**：签名完全相同才归为一组（即当前方法本身），对照组是"不分桶，每个实例单独成题型"（用于量化归纳带来的压缩率）。

## Stage 4：关系推断

**失败模式**：漏判前置边、误判前置边（尤其是把 `related`/`builds_on` 误判为 `prerequisite`）、候选生成阶段漏掉真正的前置对、版本冲突边（教学顺序相反）未被正确识别为需要 Stage 5 修复的信号。

**检测手段**：候选生成召回率（金标正例进入候选的比例）；判定 P/R/F1，**在传递闭包上计算**（Stage 5 传递约简后在最终图上重算一次，二者都报告）。

**评测数据**：分层抽样候选对（按证据强度：强共现、仅时间顺序、仅显式引用等分层），每层 ≥ 50 对，共约 200～250 对首轮标注；人工核验约 40～50 对。

**阈值与动作**：候选召回率 ≥ 0.95；判定 F1 ≥ 0.80（前置关系比实体消解更依赖语义推理，阈值适当放宽，但需在错误分析中说明主要错误类型）。不达标 → 补充证据特征或调整候选生成规则。

**基线**：同主线内引入顺序相邻即为前置。

## Stage 5：版本对齐、补全与约简

**失败模式**：顺序冲突修复位置不最小（前移过多，掩盖真实教学位置）、缺口补全遗漏（课标条目未被覆盖）、补全的知识点定位错误（学段/前置关系不合理）、修复引入环（理论上不应发生，但需检测）。

**检测手段**：不变量——自洽条件 100%（每条前置边 A→B，A 引入不晚于 B）、被引用知识点均存在、修复后图无环；完整性——课标条目逐条映射覆盖率 100%（个别不适用条目逐条写理由）；`reconciled` 条目由模型组按 4.3 节流程审阅，最终停顿点抽样交用户核验。

**评测数据**：全部 `reconciled` 条目（预计数量待 Stage 5 实测，若 >150 条则分层抽样核验，否则全量核验）。

**阈值与动作**：自洽/完整性不变量必须 100%（硬门槛，不达标不得进入 Stage 6）；`reconciled` 条目人工核验通过率 ≥ 0.90，低于则重新审阅未通过部分。

**基线**：无（对齐问题必须解决，无"更简单方法"作对照；用"移动的引入位置数/补全的知识点数"衡量修复的最小性，越小越好但不设固定基线数值，在 `reports/editions.md` 中说明每一处的必要性）。

## Stage 6：能力边界推导

**失败模式**：`grants` 遗漏能力维度、`grants` 增量归属错误课时、单调折叠实现错误导致边界非单调、校验函数漏判某一维度的越界。

**检测手段**：不变量——单调性（后续课时边界不小于前面）、每个教材实例都不超出所在课时边界（若超出，说明 `grants` 或抽取有误，回溯修正）；越界探针——覆盖边界每个维度各构造若干条已知越界题，查准查全；同时补测 Stage 3 生成探针的边界通过率。

**评测数据**：越界探针由模型组按维度（整数数域、小数位数、分数类型、运算操作数形态、概念、计量单位、几何词汇）各构造 ≥ 15 条边界内 + 15 条越界题，共约 200+ 条，覆盖各年级；最终停顿点抽样核验约 40 条。

**阈值与动作**：越界探针查准查全均 ≥ 0.95（这是验证闭环直接依赖的能力，阈值从严）；生成探针边界通过率 ≥ 0.98。不达标 → 回溯对应知识点的 `grants`。

**基线**：无（首次交付的能力）；用"实例超出所在课时边界的比例"作为内部一致性基线，目标为 0。

## Stage 7：查询接口（检索探针）

**失败模式**：别名未收录导致检索不到；跨单元综合类需求命中不全；返回结果与教师意图的年级/单元定位不符。

**检测手段**：检索探针——约 60 条教师口吻需求（见 `eval/probes/retrieval_probes.md`），计算 recall@5、MRR。

**评测数据**：60 条探针即评测数据本身，标准答案（应命中的知识点 ID 集合）由模型组按 4.3 节生成，最终停顿点抽样核验。

**阈值与动作**：recall@5 ≥ 0.85、MRR ≥ 0.7。不达标 → 先看基线（TF-IDF）差距多大，若检索方法本身不达标再迭代（如引入别名扩展、领域/年级过滤）。

**基线**：对名称、别名、描述做 TF-IDF 检索。

## Stage 8：端到端评测

汇总以上全部组件指标 + 三个下游探针，在 test 集上运行（开发过程不看 test 集样本）。产出 `reports/eval.md`：各指标数值与 CI、相对基线提升、主要失败类别与典型案例、已知局限。

## 金标标注模型组（试标前的初步计划，试标后据一致性与成本定稿）

- 首轮独立标注：`qwen-flash` + `deepseek-v3.2`（不同厂商，轻量、并发标注成本低）。
- 仲裁：`qwen-max`（思考模式）。
- Stage 2/4 的流水线判定（非金标）：可由 Agent 自己完成或调用 `qwen-plus`（非思考模式，按成本决定），但不得进入同任务的标注模型组。
- 最终组合以 Stage 0 第 7 步最小调用结果与试标阶段数据为准，见 `docs/decisions.md`。
