# Stage 2 评测规格：知识点实体消解

细化自 `eval/specs/overview.md` 的 Stage 2 一节，按 CLAUDE.md 4.1 节流程执行。

**输入**：`work/books/*/knowledge_points.json` 中全部 466 个局部知识点（12 本书；局部 ID 跨书有 21 个重名，全局以 `书::局部ID` 为键）。
**输出**：`data/knowledge_points.json`（规范知识点目录）、`data/kp_local_map.json`（局部→规范映射，覆盖全部 466 个局部知识点）、`data/lessons.json` / `data/books.json`（课程结构，知识点引用改写为规范 ID）、`data/edges_extends.json`（`Edge(type=extends)`）、`data/judgments/stage2_pairwise.jsonl`（每次成对判定的 `Judgment`）。

## 1. 失败模式清单

1. **Blocking 漏召回**：真正应合并（或构成螺旋扩展）的一对知识点没有进入候选，判定环节永远看不到它。典型风险：跨主线命名不一致（如「观察物体」vs「观察物体（三视图）」、「确定位置」vs「方向与位置」）、跨领域归类不一致、名称措辞差异大。
2. **漏并（假 different）**：同一考点在不同书（尤其新旧版之间，如 g4b 与 g5a 的「小数加减法」）未合并，规范目录出现重复。
3. **误并（假 same）**：不同考点被合并，信息被抹掉。其中两类单独关注：
   - 3a. **扩展被误判为同一**（最危险）：螺旋上升的内容（「万以内数比较大小」vs「亿以内数的大小比较」）被合并，会让能力边界与前置关系全部错位；
   - 3b. **伞形复习点吞并具体点**：g6b 总复习类伞形知识点（如「小数、分数、百分数的认识（总复习）」）与具体知识点合并，把一群具体知识点通过传递性连成一个大簇。
4. **传递性误并**：两两判定都「看起来」合理，但连通分量把 A–B–C 链成一个过大的簇。
5. **扩展方向错误**：`extends` 的方向（窄→宽）颠倒，污染 Stage 4 证据。
6. **约束违反**：同一课时内被抽取者刻意区分的两个知识点被合并。
7. **映射不完整 / 引用悬空**：某个局部知识点没有映射；映射到不存在的规范 ID；规范 ID 不唯一或不符合 ID 约定。
8. **规范知识点属性合并错误**：首次引入课时不是成员中最早的；复现课时丢失；别名丢失。

## 2. 检测手段

| 失败模式 | 检测手段 |
|---|---|
| 1 Blocking 漏召回 | **锚点金标**（§3.2）上的 blocking 召回率：金标 same（及 extends）对中进入候选的比例 |
| 2 漏并 | 成对判定 `same` 类召回率（成对金标）；锚点 B-cubed recall |
| 3 误并 | 成对判定 `same` 类精确率；锚点 B-cubed precision |
| 3a 扩展→同一 | 单独指标：成对金标中 gold=`extends` 的对被预测为 `same` 的比例 |
| 3b 伞形吞并 | 不变量：规范簇大小分布，簇 > 4 个局部成员的逐个列入错误分析；成对金标中含「总复习」知识点的对单独统计误并数 |
| 4 传递性误并 | 锚点 B-cubed precision（直接衡量簇级误并）；最大簇大小监控 |
| 5 方向错误 | 成对金标中双方都判 `extends` 的对，方向一致率 |
| 6 约束违反 | 不变量（pytest）：同一课时的 `intro_knowledge_point_ids` 中两个不同局部知识点不得映射到同一规范 ID |
| 7 映射问题 | 不变量（pytest）：466 个局部知识点全部有映射；映射目标存在；规范 ID 唯一且符合 `kp.<领域>.<主线>.<slug>`；`data/lessons.json` 引用全部可解析 |
| 8 属性合并 | 不变量（pytest）：规范知识点 `first_introduced_lesson_id` = 成员中教学序列最早的引入课时；成员的引入/复现课时全部出现在规范点的引入或复现课时中；成员名称全部出现在 name/aliases 中 |

## 3. 评测数据

两类金标，均按 CLAUDE.md 4.3 节流程生产（指南 `eval/annotation/entity_resolution/guideline.md`）。

### 3.1 成对金标（衡量成对判定质量）

- **总体**：Blocking 产出的全部候选对（判定环节只会看到候选对，判定质量应在候选对总体上衡量）。
- **分层抽样**（按 TF-IDF 余弦相似度与来源分层，覆盖困难样本）：
  - H：sim ≥ 0.30（高相似，最可能 same，也是「扩展误判为同一」的主要来源）；
  - M：0.15 ≤ sim < 0.30；
  - L：sim < 0.15 且来自 TF-IDF 路；
  - T：仅来自「同主线相邻学期」路（TF-IDF 未召回）。
  - 每层 90 对，共 360 对。样本量依据：成对 `same` 类精确率/召回率预期 ≈0.9，n≈140 时 Wilson 半宽 ≈0.05；H 层是 `same`/`extends` 的主要来源，按分层后 `same` 正例预期 ≥ 100 对。
- **划分**：每层内随机 50/50 划分 val / test（固定随机种子）。

### 3.2 锚点金标（衡量 blocking 召回与簇级质量，不受候选集限制）

- 抽样 129 个局部知识点作为锚点（按领域 × 年级段分层：低 1–2、中 3–4、高 5–6 年级，按各层知识点数比例分配，每层至少 4 个）。
- 标注方式（两步）：(1) **全表筛选**——两个标注模型各自看到锚点的完整信息与**全部其余 465 个局部知识点**的清单（书、名称、领域、主线），挑出可能 `same` / `extends` 的知识点，取两者并集作为宽松候选；(2) **逐对判定**——并集中每一对按 §3.1 成对金标的完整流程（完整描述 + 习题举例，盲标 + 仲裁）标注。筛选不依赖 blocking，可无偏地估计 blocking 召回（前提是两模型并集的筛选召回足够高）。
- 金标簇：锚点 + 其全部 `same` 知识点（B-cubed 在锚点条目上平均）。
- **划分**：60 val / 60 test（分层随机）。

### 3.3 标注模型组（独立性原则，CLAUDE.md 4.3.7）

- 流水线成对判定模型：`qwen3.7-plus`（Stage 2/3/4 流水线统一使用，不进入任何标注模型组）。
- 首轮盲标：`qwen3.8-flash` + `deepseek-v4.1-flash`（不同厂商）；思考/非思考模式由试标决定。
- 仲裁：`qwen3.8-max` 思考模式；仲裁置信度 < 0.7 进入人工队列。
- 试标：从成对样本中取 30 对，候选配置全部跑一遍，Agent 自己也独立标注这 30 对作为诊断参照（不进入金标），据分歧修订指南。

### 3.4 人工核验（停顿点）

- 从「一致采纳」「仲裁采纳」两层各抽样（成对 12 + 12，锚点 3 + 3 个锚点的判定集合），连同人工队列（上限 10 条，超出按置信度最低优先）；估计金标准确率（Wilson CI）写入 `reports/eval.md`。

## 4. 指标、阈值与动作

| 指标 | 定义 | 阈值 | 不达标动作 |
|---|---|---|---|
| Blocking 召回率 | 锚点金标 same 对中进入候选的比例 | ≥ 0.95 | 引入 bge-small-zh 向量召回作第二路（KICKOFF），或增大 k |
| Blocking 召回率（extends） | 锚点金标 extends 对进入候选的比例 | 报告，不设阈值（Stage 4 另有自己的候选生成） | — |
| 成对 `same` F1 | 成对金标上 `same` 类 P/R/F1 | F1 ≥ 0.85 | 错误分析 → 修订判定 prompt / 换思考模式 |
| 扩展→同一误判率 | gold=`extends` 中预测为 `same` 的比例 | ≤ 0.05（单独过线） | 修订 prompt 中扩展判据；必要时对「同主线不同数域」加规则 |
| 三分类 macro-F1 | same/extends/different | 报告 | — |
| 簇级 B-cubed F1 | 锚点上平均（另报告仅在金标簇或预测簇大小 ≥ 2 的「非平凡」锚点上的 B-cubed：多数锚点是单点簇，全体平均会被稀释，基线也能拿到 0.97） | ≥ 0.85 | 看 precision / recall 哪边低：precision 低 → 查传递性误并与约束；recall 低 → 查 blocking / 漏判 |
| 扩展方向一致率 | 双方都为 extends 的对中方向一致 | 报告 | — |

所有比例指标附 Wilson 95% CI。开发调参只看 val，test 只在阶段验收时跑一次。

## 5. 基线

**名称完全匹配合并**：两个局部知识点 `name` 字符串完全相同即判 `same`，否则 `different`；以 `same` 为边求连通分量。基线没有 blocking（其候选即名称相同的对），blocking 召回率一栏对基线报告「名称相同对」占金标 same 对的比例作为参照。

## 6. 错误分析

每次评测输出 val 上的失败对，按以下原因归类计数：`扩展误判为同一`、`漏并（措辞差异）`、`漏并（跨主线/领域）`、`伞形复习点误并`、`不同考点误并`、`方向错误`、`其他`。归类由规则先粗分（是否含"总复习"、主线是否相同、gold/pred 组合），人工/Agent 复核后记录到 `reports/eval.md`。
